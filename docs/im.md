# 员工即时通讯（聊天）

公司内部员工之间的私聊与群聊：文字（含 Unicode emoji）、图片、文件、内置表情、个人自定义表情、语音消息及前台音视频通话，提供 PC web 与移动 App 源码接入（移动 H5 是同一份代码，用于调试与自动化测试）。客户端本地优先：会话、消息、通讯录与看过的附件存在本机，打开已缓存的会话不再请求服务端。设计取舍见[设计说明](design-notes.md#im)，实时提示的载荷见[实时推送](realtime.md)。

不包含：离线推送、后台及锁屏接听、微信小程序里的聊天、好友申请、在线状态、输入中提示、转发、置顶、@提醒、免打扰、逐条已读名单与全文检索；会员等外部用户不能聊天。

服务端用例：开关与安装 [im-install.e2e-spec.ts](../apps/server/test/e2e/im-install.e2e-spec.ts)、[im-switch.e2e-spec.ts](../apps/server/test/e2e/im-switch.e2e-spec.ts)，会话与群角色 [im-rooms.e2e-spec.ts](../apps/server/test/e2e/im-rooms.e2e-spec.ts)，发送、编辑与撤回 [im-entries.e2e-spec.ts](../apps/server/test/e2e/im-entries.e2e-spec.ts)，同步与未读 [im-sync.e2e-spec.ts](../apps/server/test/e2e/im-sync.e2e-spec.ts)，通讯录 [im-directory.e2e-spec.ts](../apps/server/test/e2e/im-directory.e2e-spec.ts)，附件 [im-files.e2e-spec.ts](../apps/server/test/e2e/im-files.e2e-spec.ts)，表情 [im-stickers.e2e-spec.ts](../apps/server/test/e2e/im-stickers.e2e-spec.ts)，清理 [im-purge.e2e-spec.ts](../apps/server/test/e2e/im-purge.e2e-spec.ts)；客户端引擎 `packages/shared/src/platform/im/client/im-engine.spec.ts`，浏览器 [im-web-chat.spec.ts](../apps/web/e2e/im-web-chat.spec.ts)、[im-web-groups.spec.ts](../apps/web/e2e/im-web-groups.spec.ts)。

## 当前交付与使用前提

本次公开的是聊天及双平台原生桥源码、依赖坐标与第三方声明，不包含原生 SDK 二进制或签名 App。Web/H5 自动化、原生编译/链接及模拟器平台测试已有通过记录；产品宿主签名安装、Android/iPhone 真机媒体、真实 LiveKit/TURN 及删除房间后旧票据重连拒绝仍待现场验收。Android 传递依赖的版本特定再分发许可尚待上游澄清，不能把源码发布、npm 许可检查或补齐声明当作 Android 成品分发许可通过；详见[插件说明](../mobile/src/uni_modules/qw-livekit/README.md#许可证与-android-状态)。

语音消息不依赖 LiveKit 服务，但 App 仍需安装包含录音、SQLite 和原生授权接口的新原生包。前台音视频另需完成 [LiveKit 部署与接入](livekit.md)。

## 启用

服务端环境变量 `APP_IM` 控制是否加载本模块，默认 `false`，只在启动时读取，改动后全部实例重启。

- 关闭时：不加载模块，`/api/im/*` 一律 404；不注册 `im.purge` 任务的处理器（任务行不排定时）；web 顶栏没有聊天图标，移动端消息 tab 只有通知。客户端靠 `GET /api/im/options` 判断：200 显示入口，404（开关关闭、套餐不含聊天）或 403（不是员工）隐藏入口；断网或 5xx 时，本机有该账号的缓存就照常显示。
- 表照常由迁移创建，参数、任务行与菜单分组照常由种子写入，与开关无关；打开开关不需要额外的迁移。
- 聊天附件用两个内部存储标签 `im.attachment`、`im.sticker`。不论开关，通用存储接口（上传、详情、下载、内容、删除、列表、导出）对它们一律拒绝或不列出，包括上传者本人与 root；附件只能经聊天自己的文件路由按会话成员读取。
- 多租户打开时，聊天受租户套餐控制：种子建一个隐藏的顶层分组「聊天」（`route_name` 为 `im`，没有页面与权限），第一次建出时自动加进全部现有套餐，升级后已有租户不丢聊天；之后 root 从某个套餐里去掉它，种子不会再加回。套餐不含「聊天」的租户，员工访问 `/api/im/*` 回 404，入口不出现。默认租户与多租户关闭时不受套餐限制。`APP_IM=false` 时套餐编辑与角色授权树不显示这个分组。
- 只有内部员工（`user_type='admin'`）能用，其它身份回 403 `B5001`。聊天没有 `im.*` 权限点、没有菜单页，任何启用的员工都能用；root 也不能越过会话成员、群角色与附件的边界。平台人员进入其他租户期间，聊天仍在本人租户。
- 演示模式（`APP_DEMO_MODE=true`）下聊天只读：写接口不在演示豁免名单里，发送、建群、上传等一律被拒。

## 用户能做什么

- **入口**：web 顶栏的聊天图标（带未读合计，超过 99 显示 99+）打开 `/im/chat`；移动 App 在消息 tab 顶部切换「聊天 / 通知」，tab 角标是站内信与聊天未读之和。
- **通讯录**：本租户全部启用员工与启用部门（不含手机号、邮箱与用户名；所在部门已停用的员工不挂在部门树下），在本机按姓名或部门子树搜索，点人直接私聊；它不受管理数据范围限制。
- **私聊**：同一对员工只有一个会话；对方被停用后不能再给他发消息。
- **群聊**：建群者为群主，其余为成员，人数上限见参数 `im.group.max_members`（含群主）。

  | 操作                 | 群主                             | 管理员       | 成员 |
  | -------------------- | -------------------------------- | ------------ | ---- |
  | 加人、改群名         | ✓                                | ✓            |      |
  | 移出成员             | 任何其他人                       | 只能移出成员 |      |
  | 设或取消管理员、转让 | ✓                                |              |      |
  | 解散                 | ✓                                |              |      |
  | 退群                 | 只剩自己时（即解散），否则先转让 | ✓            | ✓    |

  群主账号被停用、删除或不再是员工时，任一管理员（没有管理员时任一成员）可以把群主转让出去。新成员看不到入群之前的消息，退群后再加入也看不到离开期间的内容。群解散后成员仍能读保留期内的历史、可以退群，不能再发送、编辑、撤回或管理。成员、角色、群名与解散的变化都在会话里留一条系统消息。

- **消息**：文字（去首尾空白后不能为空，换行与制表符之外的控制字符被拒，始终按纯文本显示）、emoji、图片（服务端生成 ≤360px 的 webp 缩略图，列表只下载缩略图，点开才下载原图；动图缩略图取第 1 帧）、文件、24 个内置表情、自定义表情。
- **自定义表情**：每人最多 100 个，上传或把收到的图片、表情"添加到表情"，都规范化为 ≤240px、≤512KiB 的 webp（动图最多 100 帧）。发出的表情是服务端复制的一份新附件：之后删掉收藏不影响已发的消息，撤回消息也不动收藏。
- **编辑**：只能改自己的文字，在发送后 `im.message.edit_minutes` 分钟内，不保留旧文。
- **撤回**：自己的消息在发送后 `im.message.recall_minutes` 分钟内；群主可以撤回任何人的消息，管理员只能撤回当前角色为成员的人的消息（作者已退群、被降级或账号已停用都算成员），`im.message.group_recall_anytime=true` 时不限时间，`false` 时同样受撤回分钟数限制。撤回清掉内容并删除附件；系统消息谁都不能撤回。
- **已读与未读**：消息显示出来才算读到，读位置在本人的各设备间同步；每个会话的未读最多计 100（显示 99+），不计自己的消息、系统消息与已撤回的消息。

## 参数

都在「系统参数」页，分组 `im`，种子只在插入时写值，之后归管理员；数值越界或非法时按默认值处理。

| 参数                              | 默认                                     | 说明                                                                                                   |
| --------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `im.history.retention_days`       | 180（0–36500，0 为永久）                 | 聊天记录保留天数；**只有 root 能改**                                                                   |
| `im.sync.epoch`                   | 首次种子写入的随机 UUID                  | 改值让所有客户端删除本地缓存并重建，见[保留与恢复](#保留与恢复)；**只有 root 能改**                    |
| `im.message.text_max_chars`       | 5000（1–20000）                          | 一条文字的最多字数（按 Unicode 码点）                                                                  |
| `im.message.recall_minutes`       | 2（0–1440，0 为不能撤回自己的消息）      | 以原发送时刻计                                                                                         |
| `im.message.edit_minutes`         | 5（0–1440，0 为不能编辑）                | 以原发送时刻计，编辑不延长                                                                             |
| `im.message.group_recall_anytime` | `true`                                   | 群主与管理员撤回他人消息是否不限时间                                                                   |
| `im.group.max_members`            | 200（2–2000）                            | 含群主；调小只拒绝新加人，不移出已有成员                                                               |
| `im.file.max_mb`                  | 20（1–1024）                             | 图片与文件的大小上限，实际取它与 `storage.max_size_mb` 的较小值；改大时同步调整 nginx 的上传上限       |
| `im.file.exts`                    | `pdf,txt,doc,docx,xls,xlsx,ppt,pptx,zip` | 可发送的文件扩展名，与 `storage.allowed_exts` 取交集；图片固定为 `jpg,jpeg,png,gif,webp`（同样取交集） |
| `im.voice.max_seconds`            | 60（1–300）                              | 语音时长上限；服务端解析实际文件，客户端时长不能覆盖它                                                 |
| `im.voice.max_mb`                 | 5（1–20）                                | 语音字节上限，实际与存储上限取较小值                                                                   |
| `im.call.enabled`                 | `false`                                  | 管理员运行时允许新通话；还须配置 LiveKit；关闭后继续清理已有通话                                       |

固定值（不是参数）：自定义表情每人 100 个、≤512KiB、≤240px；缩略图 ≤360px；图片解码最多 4000 万像素，超过或解不开时回 422，可以改按文件发送；客户端每个会话本地最多留 2000 条，附件缓存 200MiB。

## 保留与恢复

- 每日任务 `im.purge`（默认 03:50）逐租户执行，停用或到期的租户照样清理。保留天数大于 0 时，从每个会话最早的消息起，删除**连续的**过期消息（遇到一条未过期的就停），附件随之软删；文件本体再由 `audit.purge` 在 `audit.retention_days` 之后删除。客户端在下一次全量同步时删掉本地已过保留期的消息。
- 上传后 24 小时还没有发出去的附件（发送失败、放弃发送）由同一任务回收。
- **恢复备份或重置数据库之后，由 root 把 `im.sync.epoch` 改成一个新值**（任意新字符串，例如新的 UUID）。客户端的本地缓存里有恢复之前的会话、消息编号与读位置，与恢复后的库对不上；epoch 一变，所有客户端下次同步时整库删除本地缓存并从服务端重建。不恢复数据时不要改它，否则所有人都要重新下载一遍。要通过参数管理页面（或参数接口）改：服务端把参数值缓存在 Redis 里，直接在库里改、或者只恢复库而不动 Redis 时，缓存里还是旧值，客户端看不到变化；只能改库时，改完要清掉参数缓存（参数管理的刷新缓存，或删除 Redis 里的 `qw:param:*` 键）。

## 本地缓存

- **存在哪里**：web 与移动 H5 用 IndexedDB，库名 `qw-im-<16 位十六进制>`，按服务地址、租户与用户区分；App 用 SQLite（库文件在 `_doc/`），附件存在 App 的文件目录。缓存的内容：会话列表、每个会话最近 2000 条消息、待发送的消息、通讯录、自定义表情，以及缩略图、看过的原图和表情（合计 200MiB，按最近使用淘汰）。头像走浏览器与系统的 HTTP 缓存。
- **何时请求服务端**：冷启动、实时连接重连、回到前台，以及实时连接断开期间每 60 秒做一次全量同步（只回本人全部会话的一行摘要，没变化时 304）；平时靠实时提示只拉变化的那个会话。通讯录与表情列表第一次打开聊天时才取，之后带 `If-None-Match` 复验。
- **何时清除**：只有主动退出登录、会话被踢（含 App 在另一台设备登录）、换账号登录（登录成功时删掉本机其它账号的 `qw-im-*` 库）、`im.sync.epoch` 变化。web 的其它标签页同时放手，App 同时删除 SQLite 库与附件缓存。
- **只锁定、不清除**：会话过期（刷新令牌被拒）时停止同步、不再显示缓存，同一账号重新登录后直接复用；断网、429 与 5xx 既不清也不锁，照常显示本地记录。
- **多个标签页**：web 与 H5 只有一个主标签页负责同步与发送，其它标签页读同一个库；主标签页关闭后自动交给另一个。
- **存储空间不足**：浏览器报配额不足时，本次改用内存缓存并提示一次；关闭页面后要重新同步，未发出的消息不丢。
- 本机缓存在退出登录之前一直保留在设备上；公用电脑用完请退出登录。

## App 要求

- 本地缓存用 App 的 SQLite 模块：`mobile/src/manifest.json` 的 `app-plus.modules` 已加 `"SQLite": {}`。这是原生层变化，**必须重新打整包**（云打包或自定义基座），只发 wgt 的旧安装包没有这个模块。见[移动端指南](mobile.md#聊天)。
- App 可以发送任意文件：用 Native.js 调系统文件选择（安卓 `ACTION_OPEN_DOCUMENT`，iOS `UIDocumentPickerViewController`），不需要插件。选中后先按 `GET /api/im/options` 的扩展名与大小检查，通过才复制到 App 自己的目录再上传，发送成功或失败过期后删除副本，取消选择不留文件。
- App 下载附件走同源输出（`proxy=1`，登录令牌不会发给对象存储），上限 20MiB：收到超过 20MiB 的文件时提示"请在电脑端打开"。
- 微信小程序不显示聊天：客户端在小程序上不探测、不显示入口；分包与内置表情图片仍随产物发布。
- App 的长期会话与单 App 会话见[移动端指南](mobile.md#app-长期会话与单-app-会话)：聊天依赖 App 长期保持登录，被另一台设备顶下线时清除本机聊天缓存。

## 语音消息

点击录音、确认发送，可取消录制；失败后沿用原消息编号重试。Web/H5 复用 recorder-core，App 复用系统 RecorderManager，统一上传 WAV（PCM signed 16-bit little-endian、1/2 声道、8000/16000/44100Hz）。服务端同时核对文件结构、编码、实际时长和大小，拒绝改后缀的非音频、浮点 PCM 和不支持的采样率，不自行实现编解码或重采样。

语音仍是 IM 私有附件：只有当前合法成员可读，不能通过通用存储接口绕过；撤回、保留期与未发送附件回收沿用原规则。Web/H5 录音 Blob 随发件箱存入 IndexedDB，App 复制到 `_doc/im-outbox/`，成功、过期或主动丢弃时清理。刷新后仍可重试，不依赖临时 blob URL。一次只播放一条；离开会话、撤回、锁定、退出、换账号及清库立即停止录音和播放。

## 前台音视频通话

在私聊中呼叫对方，或在群聊中选人（含本人最多 8 人）；接听前不开麦克风和摄像头。可静音、启停摄像头、切换前后镜头、选择内置扬声器偏好和挂断。Web 使用 LiveKit 官方 JS SDK，App 使用 [qw-livekit 原生插件](../mobile/src/uni_modules/qw-livekit/README.md)，不通过 WebView 传递媒体凭据。

通话要求当前员工、租户套餐、房间成员时期和登录会话均有效。邀请 45 秒，心跳每 5 秒，失联 30 秒结束，单次最多 2 小时。首次接听绑定本次登录会话，其他设备不能接管；群聊中正常离开的非发起者，在仍有至少两位参与且原会话、成员时期有效时可主动重新加入。发起者离开、私聊任一方离开、成员被移除、房间解散、任一参与登录结束或资格失效，会结束整次通话。

浏览器通话要求 Web Locks，沿用聊天主标签页持有媒体；其他标签页可继续聊天，通话入口提示由主标签页操作。缺少 Web Locks 时明确禁用通话，语音消息不受此限制。同一聊天房间只有一个尚未完成清理的通话；没有跨所有设备的“员工全局占线”约束。界面区分等待接听、媒体连接/重连及结束中；获得票据不代表媒体已接通。结束摘要只写一条系统消息，包含类型、原因与时长，不保存录音录像；时长止于首次停止业务授权，不把后续媒体删除重试时间计入。

LiveKit 控制面暂时不可达时保持结束中，后台持续清理，确认独立媒体房间已删除且无未知创建后才释放房间槽。已有连接不会因短 JWT 到期立即断开；正常群成员离开也可能有尚未过期的旧票据。缺少服务配置时明确显示不可用，语音消息仍独立可用。部署配置、TURN 和旧票据重连核对见 [LiveKit 部署](livekit.md)。

## 已知上限

- **S3 预签名窗口**：使用 S3 存储时，web 读附件由服务端先核对成员身份，再 302 到一个 60 秒有效的预签名地址；这 60 秒内拿到这个地址的人都能下载，撤回或退群也收不回已经发出的地址。web 读私有附件因此同样需要 S3 的 CORS 与 `CSP_CONNECT_SRC`（见[部署](deploy.md#文件存储s3-直传与私有下载)）。
- **全量同步的规模**：全量同步每次返回本人全部会话（每个会话一行六个数字），服务端每次都查库，ETag 只省传输。每人几百个会话没有问题；单人上千个会话时响应变大，那时需要改成按用户修订号的增量流（见[设计说明](design-notes.md#im)）。通讯录同样全量返回，按数千名员工的规模设计。
- 实时提示丢失时由下一次全量同步补上；对方撤回消息后本地未读数可能暂时偏高，下次全量同步纠正。
- 发送自定义表情每次复制一份小文件（≤512KiB），不按内容去重。
- 演示模式下聊天只读。
- App 的真机表现（SQLite 读写与清除、选文件发送、打开文件、长期会话）需要在目标设备上核对，见[移动端的真机核对](mobile.md#4-真机核对)。
