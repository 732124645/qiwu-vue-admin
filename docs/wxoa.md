# 公众号管理

「公众号」菜单分组管理一个或多个微信公众号：账号管理、会话、消息记录、自动回复、自定义菜单、粉丝管理（含标签与黑名单）、素材管理、模板消息、渠道二维码，以及图文草稿、发表记录、群发、数据统计、留言和订阅通知。设计取舍见[设计说明](design-notes.md#wxoa)。

模块默认关闭，见[启用](#启用)。只管理公众号（服务号、公众号（原订阅号）、公众平台测试号）。仓库里的 `wx_mp` / `wxMp` / `WX_MP_*` 指小程序登录与订阅消息，凭据在环境变量里，与这里的代码互不复用。本模块不包含支付、卡券、第三方平台代授权、客服账号与会话分配、网页授权与 JS-SDK；订阅通知只能发送给已经通过其它途径完成授权的粉丝。

## 启用

服务端环境变量 `APP_WXOA` 控制是否加载本模块，默认 `false`，与 `APP_MULTI_TENANT` 一样只在启动时读取，改动后全部实例重启。

- 关闭时：不加载模块，`/api/wxoa/*`（包括回调地址）一律 404；不注册 `wxoa.fan.sync`、`wxoa.message.purge` 两个任务的处理器，任务表里的这两行不排定时（手动执行记一次失败）；不访问微信。侧栏与角色授权树不显示「公众号」分组，「菜单管理」照常列出它；角色已有的公众号菜单授权在编辑授权时原样保留，重新打开后照旧生效。演示种子不建公众号样例账号。
- 表照常由迁移创建，与开关无关；字典、参数、菜单与任务行照常由种子写入。
- 打开时行为不变。

## 验证情况

- 对微信接口的调用（取令牌、菜单、粉丝、标签、素材、模板消息、二维码、客服消息、配额）由模拟上游的自动化测试覆盖，请求的路径与报文按微信官方文档实现。
- 图文草稿、发布、群发、统计、留言和订阅通知同样只经假网关验证；测试覆盖管理接口的请求体、租户边界、幂等与回执处理。认证服务号的真实权限和字段差异仍需在真实账号上核对。
- 明文模式的回调由本机签名请求的端到端测试覆盖。
- **兼容模式、安全模式的回调与 IP 白名单提示只经官方示例向量、自建测试向量与模拟上游验证，未在正式公众号上核对。** 生产环境启用兼容或安全模式之前，先在自己的正式号上按[加密方式](#加密方式)的顺序核对一次：保存服务器配置成功、发一条消息能收到自动回复。

## 配置项

在「账号管理」新建账号：

| 字段           | 说明                                                                        | 测试号                 | 正式号                                   |
| -------------- | --------------------------------------------------------------------------- | ---------------------- | ---------------------------------------- |
| 名称           | 本系统里显示的名称                                                          | 自定                   | 自定                                     |
| AppID          | `wx` 加 16 位十六进制；添加后不可修改                                       | 测试号页面的 appID     | 公众平台开发配置里的 AppID               |
| 类型 / 已认证  | 服务号、公众号（原订阅号）、测试号；未认证的账号很多接口没有权限（`B6003`） | 测试号                 | 按实际选择                               |
| AppSecret      | 32 位十六进制                                                               | 测试号页面的 appsecret | 公众平台开发配置里获取或重置             |
| Token          | 3–32 位字母数字，自己定，与微信那边填的一致                                 | 测试号「接口配置信息」 | 公众平台「服务器配置」                   |
| 加密方式       | 明文 / 兼容 / 安全，与微信那边一致                                          | 只能明文               | 见[加密方式](#加密方式)                  |
| EncodingAESKey | 43 位字母数字，兼容与安全模式必填（否则 `B6008`）                           | 没有                   | 「服务器配置」里生成，与本系统填同一个值 |
| 启用           | 停用后，除账号本身的编辑、启用与删除外，各页面的操作报 `B6011`；回调回 404  | —                      | —                                        |

- 三项密钥只写不读：经 `SecretBox` 加密存库（密钥由服务端 `APP_SECRET` 派生，更换 `APP_SECRET` 后要重新填写），详情只显示“已设置”；编辑时留空表示不变，换密钥就重新填写。修改 AppSecret 或删除账号会清掉该账号的 access_token 缓存（缓存按账号 id 存放，同一 AppID 删除后重新接入的新账号不会拿到旧令牌）。
- AppID 不可修改：openid、media_id、菜单、二维码 ticket 都只对原 AppID 有效。换公众号请新建账号；同一 AppID 删除后重新接入得到新账号，旧的粉丝与消息不会回到新账号下。
- 删除账号只删除账号本身，粉丝、消息等数据保留。
- 多租户开关打开时，一个 AppID 在全部租户里只能接入一个存活的账号（另一个租户再添加回 409）。新建账号先用提交的 AppSecret 向微信换一次令牌，证明添加者确实持有这个公众号，失败时报微信的错误码、不建账号、不占用 AppID；平台人员可在租户管理按 AppID 查是哪个租户占用，释放方式见[多租户指南](multi-tenancy.md#全局唯一值的释放)。

### 测试号

1. 用微信扫码登录公众平台测试号页面（`https://mp.weixin.qq.com/debug/cgi-bin/sandbox`），得到 appID 与 appsecret。
2. 在「账号管理」新建账号：类型选测试号、加密方式明文，填 AppID、AppSecret 和自己定的 Token。保存后页面显示服务器地址（URL）。
3. 回到测试号页面，在「接口配置信息」里填这个 URL 与同一个 Token 并提交：微信会发一次 GET 验证，通过即保存成功。之后关注测试号或给它发一条消息，账号的“最近推送”即更新。
4. 在「账号管理」点“测试连接”，确认能取到 access_token。

### 正式号

1. 在公众平台的开发配置里取得 AppID、AppSecret，并把本服务器的出口 IP 加入 IP 白名单（见 [IP 白名单](#ip-白名单)）。
2. 在「账号管理」新建账号，类型与认证状态按实际选择，加密方式先与公众平台当前的设置一致（还没启用服务器配置时选明文或兼容）。
3. 在公众平台的「服务器配置」里填 URL、Token、EncodingAESKey 和消息加解密方式，提交通过后启用。按微信的规则，启用服务器配置后公众平台后台设置的自动回复与自定义菜单不再生效，改由接口（本系统）管理。
4. 点“测试连接”：依次检查取 access_token 和调用一次接口（IP 白名单），失败时显示原因。

## 回调地址

- 地址是 `<浏览器当前源>/api/wxoa/callback/<key>`，页面上有复制按钮。`key` 由服务端生成（22 个字符），不可修改。
- 后台与公网访问地址不同源（例如内网打开后台、公网域名给微信）时，把前缀换成微信能访问到的公网地址，路径不变。微信要求 URL 使用公网的 80（http）或 443（https）端口。
- 反向代理按现有的 `/api/` 规则转发即可（见[部署要点](deploy.md#nginx-反向代理与-csp)）；推送请求体上限 64 KiB，超过回 413。
- 回调是公开接口，不需要登录，只认签名。`key` 会出现在访问日志的路径里；只凭它伪造不了推送（还要 Token 签名）。Token 泄露时在本系统和公众平台同时更换。
- 验证失败（未知 key、账号停用或已删除、时间戳超出 ±300 秒、签名不符等）一律回 404。同一来源 IP 对同一账号 60 秒内验证失败超过 120 次后，这个 IP 对这个账号的所有请求（包括签名正确的推送和 GET 校验）在窗口剩余时间内都回 429，不再验签，只影响这个 IP 上的这个账号；验签通过的请求不计入失败次数。更换 Token 时，公众平台提交配置会立即用新 Token 发 GET 校验，所以先改本系统、紧接着改公众平台，最好在低峰期操作；期间的失败若超限，最多影响约 60 秒。计数按来源 IP，所以服务端的 `TRUST_PROXY` 必须设成实际反向代理的地址（见[部署要点](deploy.md#构建产物与环境)），否则所有请求都计在代理这一个 IP 上。

## IP 白名单

- 正式号调用接口要求服务器的出口 IP 在公众平台的 IP 白名单里；多实例或经 NAT 出网时，每个出口 IP 都要加。测试号没有 IP 白名单。
- 不在白名单时接口报 `B6004`，提示里显示微信报告的那个 IP，加入白名单后重试。这个 IP 从微信的错误信息里提取，提取方式未在正式号上核对；提取不到时只显示错误本身。

## 加密方式

- **明文**：消息不加密，只建议测试号使用。微信的 `signature` 不覆盖请求体，本系统另把每个签名与请求体摘要绑定 600 秒：同一签名换了请求体即拒绝，原样重发视为微信重试。
- **兼容 / 安全**：本系统对推送都要求密文（`encrypt_type=aes`、`Encrypt` 与 `msg_signature`），兼容模式下也只用密文部分，没有密文的推送被拒，防止被剥掉密文降级为明文；被动回复都加密。所以这两种模式在本系统里行为相同，区别只在微信那边。
- 保存服务器配置时的 GET 验证在任何模式下都只验 `signature` 并原样回 `echostr`。

切换加密方式按下面的顺序，不丢推送也不丢回复：

| 方向                | 第一步           | 第二步                                          | 第三步           |
| ------------------- | ---------------- | ----------------------------------------------- | ---------------- |
| 升级（明文 → 安全） | 公众平台改为兼容 | 本系统改为兼容或安全（填同一个 EncodingAESKey） | 公众平台改为安全 |
| 降级（安全 → 明文） | 公众平台改为兼容 | 本系统改为明文                                  | 公众平台改为明文 |

顺序反了的后果：本系统先于公众平台离开明文时，明文推送会被拒（404）；公众平台已是安全模式而本系统仍回明文时，粉丝会看到“该公众号暂时无法提供服务”。

## 5 秒、重试与排重

- 微信等待回复约 5 秒，收不到就重试，共 3 次。本系统在回调请求里只做本地工作：验签、写消息与粉丝、按规则生成被动回复，不调用微信接口；内部预算 4 秒，超时回 `success`。
- 补粉丝资料、二维码计数与自动打标签、模板消息回执、入站媒体副本、实时提示都在回复之后处理；进程恰好在这时崩溃会丢这些后续处理（见[设计说明](design-notes.md#wxoa)）。
- 排重只靠数据库唯一键：普通消息按 MsgId，事件按发送者、时间、事件类型、EventKey 与回执编号。重复的推送回 `success`，不再处理。
- 位置上报（`LOCATION`，可能每 5 秒一条）不入库。本系统不认识的消息或事件类型只保存公共字段并回 `success`；单条内容超过 16 KiB 时截断保存并标记，照常回复。

## 自动回复

- 关注事件：通过渠道二维码关注的，先找该二维码场景的扫码规则，没有再用关注规则；已关注用户扫码只找扫码规则；菜单点击找 KEY 相同的点击规则；文字消息和语音识别结果找关键词规则（优先级高的先，同优先级精确先于包含）。都没命中时，用户发来的消息用默认规则，事件不回复。
- 比较前做 Unicode 规范化、去首尾空白，拉丁字母不分大小写。规则不缓存，改动立即生效；每个账号最多 500 条，关注规则和默认规则各只能启用一条。
- 回复文本不能含 XML 不允许的控制字符（微信会拒收整条回复），保存时即拒绝。

## 消息与会话

- 客服消息有两个发送窗口：粉丝发消息后 48 小时内最多 5 条；粉丝点菜单（点击、扫码推事件）、关注、已关注扫码后 1 分钟内最多 3 条。打开网页或小程序的菜单与位置上报不开 1 分钟窗口。两个窗口如何叠加以微信为准：本系统只按时间预检，两个窗口都已过期时报 `B6007`，条数以微信的返回为准。
- 客服消息的图片、语音、视频只能用本账号的永久素材，或会话里粉丝发来的媒体副本；新文件请先在「素材管理」上传。
- 会话页的按钮权限是 `wxoa.message.send`，读取会话要「消息记录」页的 `wxoa.message.browse`，角色须同时授予。
- 新消息到达时推送 `wxoa:message`（只带账号与消息 id，见[实时推送](realtime.md)），会话页收到后合并 1.5 秒内的提示再重新拉取。
- 参数 `wxoa.media.copy_inbound`（默认开）：粉丝发来的图片、语音和视频缩略图复制到本地存储（微信的临时媒体只保留 3 天）。语音是 amr 格式，浏览器不能播放，页面提供下载并显示微信的语音识别文本（如有）。
- 参数 `wxoa.message.retention_days`（默认 180，0 为永久）：任务 `wxoa.message.purge` 每天物理删除过期消息与入站消息的本地副本，并把创建超过 10 分钟仍未发出的消息标为失败。清理覆盖全部未删除的租户，停用、到期或套餐不含公众号的租户也照样清理：清理不调用微信，保留期对已存数据始终有效。

## 图文草稿与发表

- 「图文草稿」保存本地草稿，每篇草稿含 1–8 篇文章。正文使用现有富文本编辑器，服务端再次按公共富文本白名单清洗；每篇清洗后的 HTML 不得超过 20,000 个字符。封面必须是当前账号自己的永久图片素材，跨账号或不可用的素材不会被接受（`404` 或 `B6102`）。
- 同步草稿时，正文图片只允许本站存储中当前账号的 `richtext` 公开对象，且必须是 jpg/png、小于 1 MiB；服务端通过内部对象读取后上传到微信并替换 URL。同一个对象在同一账号下只上传一次。已经是 `mmbiz.qpic.cn` 的图片会改为 HTTPS 保留；外链、gif/webp、超限、找不到或不符合属主条件的图片会从推送内容删除，并在响应中列入“未同步图片”。服务端从不按编辑器的 URL 发起外部请求。
- 从微信草稿箱拉取时先使用 `no_content=1` 拉列表，再逐条获取正文。微信返回的原排版样式经过同一套清洗后保存，页面会提示样式可能丢失；超长或无法清洗的条目列在“未能拉取”中，不影响其它条目入库。预览只渲染安全的 HTML，远程图片仅允许 `mmbiz.qpic.cn` 与 `mmbiz.qlogo.cn`，并在预览文档首部设置 `no-referrer`。
- 「发表记录」提交已同步的草稿到 `freepublish/submit`，回执通过公众号入站处理器更新状态、文章链接和失败篇序号。草稿有本地未同步修改时发布或群发返回 `B6101`；超过两分钟仍在发布中的记录打开列表时补查一次。删除发表记录会调用微信删除接口，操作不可恢复。

## 群发

- 群发对象是全部粉丝、当前账号的标签，或 2–10,000 个 openid。消息类型支持文字、图片、语音、视频和图文（图文引用已同步草稿）。标签、粉丝和草稿都按账号归属检查，跨账号或跨租户的 id 统一返回 `404`。
- 发送前可以预览给一个粉丝；正式群发会记录本地任务、`clientmsgid` 和微信回执，重复提交在 24 小时窗口内幂等。按 openid 群发时重复的 openid 先去重，保存和发送的都是去重后的列表。提交结果未知（例如网络超时）的任务在记录列表里提供“重发”，沿用原 `clientmsgid`，微信按它防重；微信回 45065 并带回上次的 `msg_id` 时任务记下它，回执照常对上。微信只在 24 小时内按 `clientmsgid` 防重，所以创建超过 23 小时的任务不再允许重发（`B6103`），页面也不再显示重发按钮。`MASSSENDJOBFINISH` 回调更新总数、过滤数、成功数、失败数和原创校验结果，记录列表显示其中的总数、成功数与失败数。删除群发记录只删除本地记录或调用微信允许的删除操作，页面会二次确认。
- 服务号每月次数、订阅号每日次数只在页面提示并要求二次确认，最终以微信返回为准；未认证账号或测试号没有对应能力时映射为 `B6003`。

## 数据统计、留言与订阅通知

- 「数据统计」支持用户增减、消息、接口和图文的统计。查询区间最多 90 天，按上游接口允许的窗口串行拆分；今天的数据不请求，历史结果按账号和日期缓存 24 小时。统计不建本地业务表。图文统计只用账号级的每日汇总 `getbizsummary`（每次最多 30 天）；单篇文章的 `getarticleread`、`getarticleshare`、`getarticletotaldetail` 每次只能查一天，90 天要几百次调用却不进任何图表，因此不请求。消息统计的“发消息用户”是各消息类型的人数之和，同一用户发了多种类型会被重复计入。
- 留言从「群发消息」里的图文群发记录打开：微信的留言接口只认群发返回的数字 `msg_data_id` 和文章序号（从 0 开始）。发布（freepublish）的文章能否拿到可用的 `msg_data_id` 尚未核实：官方 `freepublish/submit` 的返回字段表列出了 `msg_data_id`，是否真的返回、能否用于留言接口须在已认证服务号上核对。核实之前「发表记录」页不提供留言入口，发表记录也不保存该字段。留言按文章读取微信上游，不把留言正文落库；页面只按纯文本显示，支持打开或关闭文章留言、精选、删除、回复和删除回复。
- 「订阅通知」支持模板库、添加/删除本账号模板及最多 20 个粉丝的发送。模板列表只在 Redis 缓存 10 分钟，添加、删除会失效缓存，`refresh=true` 强制重新读取。模板事件通过回调写入消息记录，不创建或修改粉丝记录。用户授权订阅需要另行接入微信 H5 JS-SDK 开放标签，本模块不会代替授权。

## 安全与多租户边界

- 草稿正文先清洗再保存、同步和预览；图片改写只认当前账号的本站对象，不按 URL 访问外网，也不从 `/files/` 路径推导对象键。所有上游正文和接口响应都经过大小上限检查。留言正文不使用 `v-html`。
- 每张公众号业务表都有 `tenant_id` 与 `deleted_at`。账号、草稿、发表、群发、素材、标签和粉丝先校验当前租户与账号归属，再执行操作；请求中的 `accountId` 不能切换租户。原生 SQL 明确写租户和逻辑删除条件，后台任务和微信回调在账号所属租户的上下文中处理。
- 公开回调只按回调 key 找到账号，再在该账号租户内解析、写入和处理回执；账号所属租户不可用（停用、到期、套餐不含公众号，或多租户开关关闭时的非默认租户）时，回调与未知 key 一样回 404。管理接口继续使用会话租户与权限。夜间粉丝同步只处理可用租户（与回调同一判定，含套餐是否包含公众号）的账号，消息保留期任务处理全部未删除的租户；两者都逐个租户运行，一个租户失败不影响其它租户。Swagger 的 `wxoa` 标签覆盖全部管理控制器，统一列出 `B6101`（草稿未同步）与 `B6102`（封面不可用）等业务错误；参数细节以生成的 OpenAPI 为准。

## 配额

- 「账号管理」的“接口配额”逐个查询本模块常用接口今天的调用次数。某个接口今天的次数用完时报 `B6005`。
- “清零调用次数”与公众平台的“重置 API 调用次数”每月合计只能用 10 次，只在确有需要时使用。
- 测试号的接口额度比正式号低，粉丝同步等批量操作注意次数。

## 图片显示

- 不做图片代理，也不改 CSP。有本地副本时一律用本地副本（经登录态读取）：本系统上传的素材、粉丝发来的图片与语音、视频缩略图、二维码图片。
- 远程图片只显示 `mmbiz.qpic.cn` 与 `mmbiz.qlogo.cn` 两个主机，入库时把 `http://` 改成 `https://`，`<img>` 不带 Referer；部署时 nginx 已对页面发 `Referrer-Policy: same-origin`。其它主机的图片显示占位。从微信同步来的素材只记录链接、不下载。

## 权限

## 同步与多实例

- 粉丝与素材的同步在受理请求的实例后台运行，用 Redis 锁防重：进行中再点回 `B6010`；实例崩溃后状态显示“已中断”，可以重新同步。任务 `wxoa.fan.sync` 夜间全量同步粉丝，默认停用。
- access_token 只用微信的 `stable_token` 普通模式：多个实例并发获取拿到的是同一个令牌、互不作废；按账号 id 在 Redis 缓存，从不自动强制刷新。

## 演示模式

`APP_DEMO_MODE=true` 时，所有对微信的调用在发出之前被拒绝（`A0431`），后台任务与回调后的处理同样被拦，只记日志；回调的 POST 被演示守卫拒绝。种子另建一个虚构的样例账号和样例粉丝、消息、标签、菜单、回复规则与二维码，只建一次：管理员删除样例账号后不再重建，样例消息被清理后每次部署按固定编号补回。

## 其它限制

- 菜单名称按 UTF-8 计字节（一级 16、二级 60 字节），微信的实际计法未核对。
- 删除渠道二维码只删除本系统的记录：永久二维码在微信那边仍然有效、仍占数量额度，之后扫码不再计数，也不再自动打标签。
- 微信自 2021 年 12 月 27 日起不再返回粉丝的昵称和头像。
- 按标签筛选粉丝没有索引，粉丝量很大时较慢（见[设计说明](design-notes.md#wxoa)）。
