# 流程审批接入与运行边界

栖梧的流程审批使用同一个树形引擎运行树形模型与 BPMN 模型。`flowKind` 决定画法，`formKind` 决定表单来源，两者独立；创建模型后都不能修改。本文说明接入步骤与权限边界；BPMN 元素、导入和许可规则见 [BPMN 设计器](workflow-bpmn.md)，超时动作的完整规则见 [审批超时自动处理](workflow-timeout.md)。

## 模型、版本与两种画法

| 选择             | 草稿与发布                                                                           | 运行与详情                                                  |
| ---------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| `flowKind: tree` | 保存节点 JSON；发布时用 `compile(tree, fields)` 检查节点、审批人、条件字段与分支结构 | 运行发布版本的树；详情显示进度树                            |
| `flowKind: bpmn` | 保存 XML；发布时服务端解析 XML、用 `bpmnToTree` 推出树，再执行相同的 `compile`       | 运行转换后的树；PC 详情显示只读 BPMN 图，移动端不显示流程图 |

树支持开始、审批、抄送和分支。审批可选一人通过即可（`any`）、会签（`all`）、顺签（`ordered`）；分支可选排他、并行、包容。排他取第一条匹配路径；包容取全部匹配路径；两者均需默认路径。并行走全部路径，不带条件或默认路径；多条活跃路径完成后才继续汇合后的节点。

BPMN 只接受能转换成树的结构化子集：开始/结束、用户任务、发送任务、顺序流及成对的排他/并行/包容网关。不支持回环、任意跳转/汇合、脚本、服务任务、子流程、泳池、监听器或执行表达式；返工使用任务的退回、驳回动作。客户端发送的树不能替代 BPMN XML 的服务端转换。具体拒绝原因和标红位置由 [BPMN 发布规则](workflow-bpmn.md#发布规则与错误) 说明。

发布会追加 `wf_version` 快照，保存树、表单字段/schema，以及 BPMN 模型的规范化 XML。新发起使用当前发布版本；已运行实例继续使用自己的 `versionId`，编辑草稿或发布新版本不会改写这些实例。设计与运行契约可核对 [共享模型 schema](../packages/shared/src/workflow/wf-model.schema.ts)、[模型服务](../apps/server/src/modules/workflow/model/wf-model.service.ts) 和 [运行存储](../apps/server/src/modules/workflow/runtime/wf-store.ts)。

## 动态表单与自定义业务表单

| 表单来源            | 发起与重新提交                                                                                                                          | 字段权限与接入责任                                                                                |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `formKind: dynamic` | 绑定 `wf_form`；发布时快照字段和清洗过的 form-create schema；提交值由服务端按快照校验类型、必填、枚举、范围及附件                       | 节点 `access` 的 `edit/read/hide` 由服务端强制；详情不下发隐藏字段，审批/重新提交只保留可编辑字段 |
| `formKind: custom`  | `createRoute` 指向项目业务发起页，`viewComponent` 是相对 `views` 的组件路径；引擎忽略客户端 `formValues`，从业务 handler 读取真实业务行 | 节点 `access` 不控制业务表单；业务页和服务负责编辑权限、数据校验、详情与附件访问                  |

自定义表单以 `@WfBusinessHandler('<modelKey>')` 注册 provider，实现以下契约（见 [wf-handlers.ts](../apps/server/src/modules/workflow/runtime/wf-handlers.ts)）：

- `fields()` 返回条件构造和编译依赖的字段类型。
- `assertStartable(businessKey, initiatorId, tx)` 锁住业务行，验证属于发起人、仍为草稿且未绑定实例；非本人或不存在返回 404，已发起返回 409。代他人发起须另有明确的业务授权规则。
- `loadFormValues(businessKey, tx)` 读取业务值；自定义表单重新提交时再读取一次。
- `onStateChange(instance, tx)` 同步更新业务状态，与流程动作在同一事务内；抛错会一起回滚。

项目业务代码放在项目域目录，按 [代码生成与项目接入](codegen.md) 的目录规则实现。自定义详情组件接收 `businessKey` 与 `readonly: true`；组件的只读展示不能代替后端归属检查。请假示例仅允许发起人在持有退回到 `begin` 的任务时编辑业务单据。

动态表单的字段权限不是只禁用控件：[详情服务](../apps/server/src/modules/workflow/center/wf-detail.service.ts) 过滤 schema 与值，[审批服务](../apps/server/src/modules/workflow/center/wf-decide.service.ts) 丢弃非 `edit` 的提交并校验剩余值。附件还必须属于该实例且出现在调用者可读的上传字段中。审批数据列表/导出对普通 `wf.data.*` 用户继续屏蔽隐藏字段，不能通过筛选或导出恢复；root 与模型流程管理员可看全部字段。任命流程管理员因此另需 `wf.model.managers` 权限。

## 发起、办理与管理权限

1. 在流程管理中创建模型、绑定表单、配置发起范围和审批人，保存草稿并发布；模型须启用且有发布版本才能发起。配置了发起人自选审批人时，发起页按 `start-info` 返回的节点收集选择，服务端验证非空且用户启用。
2. 审批中心接口要求登录，以本人身份访问；模型/表单/实例/任务管理还需对应 `wfPerms`。实例与任务管理按发起人的部门和 owner 计算数据范围，范围外返回 404，参见 [数据权限](data-scope.md)。
3. 实例详情仅向发起人、历史或当前办理人（含委派 owner）、抄送人、具备 `wf.instance.view` 且范围覆盖实例的管理员开放。知道实例 id 不构成访问权限。

| 动作                                                 | 谁可以执行与限制                                                                                   |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 通过、驳回、退回、转办、委派、加减签、手动抄送、评论 | 任务的当前办理人；委派交还后由原 owner 继续。服务端在锁定任务后再核对身份，他人的 task id 返回 404 |
| 重新提交                                             | 持有 `begin` 任务的发起人；动态表单只改 `begin.access` 的可编辑字段，自定义表单先在业务页修改      |
| 撤回审批                                             | 该已办任务的原办理人，且模型允许、后续尚未处理；超时自动通过不能撤回                               |
| 撤销、催办                                           | 发起人；一般撤销受模型配置与实例状态约束，退回发起人的任务允许撤销；催办每实例每小时一次           |
| 改派、终止                                           | `wf.task.manage` 管理员，经管理端数据范围检查；该权限不让管理员冒充办理人执行普通审批动作          |
| 抄送已读                                             | 只更新当前用户的 `wf_cc` 行；他人记录返回 404                                                      |

每次动作在事务内先 `FOR UPDATE` 锁实例，再对任务执行带原状态的条件更新；状态已被并发动作改变时返回 409，整次动作回滚。流程状态、业务回调和通知 outbox 同事务提交；实际通知及 `wf:task` 刷新推送在提交后执行，见 [通知机制](notify.md)。

## 超时、事件与运行限制

`timeout.hours`、`remindEvery` 按自然小时计时，不按工作日或节假日日历。默认只提醒；可配置自动通过、自动驳回或转给上级。`wf.task.remind` 默认每 5 分钟扫描，运行正常时精度约 5 分钟；任务停用、积压或故障会延迟，不能把它作为严格截止时间服务。顺签待轮到的任务没有到期时间，激活时才开始计时。

自动处理仅作用于满足条件的本人审批待办；委派、加签和已处理任务有额外限制。每次超时处理写系统 `timeout` 事件并发送相应站内信/邮件；业务处理失败先回滚，再记录失败并提醒，避免静默推进。转上级的防循环、退回规则、撤回重新计时与恢复步骤统一见 [workflow-timeout.md](workflow-timeout.md)。流程管理员身份用于通知与字段访问，不自动授予实例查看或改派权限，还需菜单、权限点与数据范围。

多实例已使用 Redis 限流及 Socket.IO Redis 分片适配器，但部署须满足 [scale-out.md](scale-out.md)：Redis ≥ 7、各实例同库同前缀与密钥、等待异步订阅就绪、本地文件用共享卷或 S3。`RedisLock` 仍基于单 Redis 节点；会话列表一次 MGET 后内存分页，邮件 transport 按实例缓存。推送不保证送达，也不支持连接状态恢复，可靠数据通过 REST 补拉；见 [实时推送](realtime.md)。

`APP_DEMO_MODE=true` 时审批写动作被拒绝，只有抄送已读在精确豁免清单中；浏览流程图不代表演示环境允许真正发起或审批。完整边界见 [安全与演示模式](security.md#演示模式的精确豁免)。bpmn.io 标志在设计器、只读图及打印中必须保持可见、不遮挡、不改动，接入项目同样遵守 [水印义务](workflow-bpmn.md#bpmnio-水印义务)。

## 上线前自检

部署方应在隔离环境按以下清单检查接入行为，并记录结果。

- [ ] 树形与 BPMN 各发布一个模型，确认同样的审批、退回和版本快照行为；不支持的图结构在发布前被拒。
- [ ] 动态表单的隐藏字段不在详情/导出中，伪造只读字段不能修改；自定义表单按业务行归属拒绝他人发起和编辑。
- [ ] 用他人的实例/任务/抄送 id 核对访问边界，管理端同时核对权限点和数据范围。
- [ ] 核对自然小时、5 分钟扫描、超时事件/通知与失败恢复；图形与打印的 bpmn.io 标志可见。
