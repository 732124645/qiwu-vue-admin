# BPMN 设计器说明

> 超时自动处理见 [workflow-timeout.md](workflow-timeout.md)。

## 一句话

BPMN 只是**第二种画法**。模型在新建时选"树形"或"BPMN"（`wf_model.flow_kind`，之后不能改）；BPMN 模型用 bpmn-js 画图，发布时服务端把 XML 转换成与树形设计器相同的树（`wf_version.tree_json`），由同一个树形引擎运行。所以审批动作、审批中心、通知、超时提醒与自动处理、动态表单与自定义表单、移动端对两种模型完全一样；服务端从不采信客户端传来的树，只从 XML 重新推出。

## 两种设计器怎么选

|              | 树形（仿钉钉）                                                                                       | BPMN                                                         |
| ------------ | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 适合         | 业务人员、审批流程简单直观                                                                           | 熟悉 BPMN 的人，想要标准流程图、与其它工具交换 `.bpmn` 文件  |
| 画法         | 在节点树上点"+"添加审批、抄送、分支                                                                  | 调色板与上下文菜单拖画；"插入分支块"一次画出成对的分叉与汇合 |
| 能力         | 节点设置相同（同一个 `WfNodeSettings` 面板：审批人、多人审批方式、字段权限、条件、超时、到期后处理） | 同左                                                         |
| 只有树形有   | 零代码向导、内置模板、版本列表的"导入 JSON"                                                          | —                                                            |
| 只有 BPMN 有 | —                                                                                                    | 导入/导出 `.bpmn`；实例详情显示 bpmn-js 只读流程图           |

拿不准就用树形：它不会画出发布不了的形状。已有的树形模型可以经版本列表"导出 JSON"，再在 BPMN 设计器里"导入"得到 BPMN 画法（反过来不行）。

## 元素子集

| BPMN 元素                   | 对应的树节点                                         | 说明                                      |
| --------------------------- | ---------------------------------------------------- | ----------------------------------------- |
| 开始事件（无事件定义）      | `begin`                                              | 恰好一个；名称缺省时为"发起人"            |
| 结束事件（无事件定义）      | 流程结束                                             | 可以多个                                  |
| 用户任务（`bpmn:UserTask`） | `review` 审批                                        | 设置存在 `qw:Config`                      |
| 发送任务（`bpmn:SendTask`） | `notify` 抄送                                        | 设置存在 `qw:Config`                      |
| 排他 / 并行 / 包容网关      | `fork`（`exclusive`/`parallel`/`inclusive`）及其汇合 | 分叉 1 进多出、汇合多进 1 出              |
| 顺序流                      | 分支出线 = 路径；网关的默认流 = 默认路径             | 条件只能写在排他/包容**分叉**网关的出线上 |

其余一律不支持、发布即拒：脚本/服务/业务规则/手工/接收任务与无类型任务、子流程与调用活动、事件网关与复杂网关、中间事件与边界事件、带事件定义的开始/结束、多实例与循环标记（多人审批方式只在面板里设）、泳池与泳道、数据对象、文本注释与分组、消息/信号/错误等定义。调色板、上下文菜单与"更换类型"菜单只提供子集内的元素。

画图规则（发布时检查，违反即在画布上标红并在上方列出）：

- **不能有回环**：返工用"退回"或"驳回"。也不支持路由分支（跳到任意节点）与任意汇合。
- **分叉与汇合成对、同类型**：每个分叉网关在它的汇合网关处结束；多条线要合到一处必须经过汇合网关，不能直接连到同一个任务上。用上下文菜单的"插入分支块"画，或在面板里"添加分支"，汇合会自动配好；改分叉网关的类型时汇合跟着改。
- 没有汇合的分叉（各分支各自走到结束）只能出现在主线的末尾。
- 排他网关按出线的先后取第一个满足条件的路径，都不满足才走默认路径；顺序在面板里用"上移/下移"调整，画布上带条件的出线显示为虚线。
- 只能有一个流程：不能有泳池、泳道、协作图。
- 名称最长 64 字；元素 id 以字母或下划线开头，只含字母、数字、`_`、`-`（导入 JSON 时不合规的 id 会自动改名并提示）。

## 发布规则与错误

发布时服务端按以下顺序检查（前端设计器用同一份 `bpmnToTree`，发布前先查一次）：

1. 大小与安全：XML ≤ 80 KiB（约 90 个元素）`bpmn_too_large`；含 `<!DOCTYPE`/`<!ENTITY` `bpmn_doctype`；严格解析失败或有任何警告 `bpmn_parse`。
2. 结构与内容：`bpmn_process`（不是恰好一个流程）、`bpmn_pool`、`bpmn_unsupported`（子集外的元素或属性，含 `documentation`）、`bpmn_foreign`（外来命名空间的属性与扩展、监听器）、`bpmn_expression`（条件不是 `qw-rule` JSON，或任何文字含 `${`）、`bpmn_condition_misplaced`、`bpmn_ref`（悬空或错误的引用）、`bpmn_di`（图形信息缺失、多余或带颜色；节点小于 10 × 10 或互相重叠；连线少于两个不重合的点、首尾不在起点与终点图形上，或经过、贴近（5 px 内）其他节点）、`bpmn_id`、`bpmn_start`、`bpmn_arity`（连线数量不对）、`bpmn_unreachable`、`bpmn_cycle`、`bpmn_join_type`、`bpmn_unstructured`、`bpmn_config`（`qw:Config` 不合规，例如夹带 `next`）。
3. 转换出的树再过树形的 `compile`（审批人、默认路径、条件字段与类型、并行路径无条件、节点数上限等，与树形设计器相同）。

服务端的 400 中 `errors[].path` 为 `xml.<元素 id>`（没有具体元素的为 `xml`），设计器据此标红。存草稿只查第 1 步，允许画到一半。

节点设置放在 `extensionElements` 的 `qw:Config` 里（命名空间 `urn:qiwu:bpmn:1`），正文就是对应树节点去掉 `id`/`type`/`name`/`next` 后的 JSON，按节点类型严格校验；条件写成 `<bpmn:conditionExpression language="qw-rule">`，正文是树形的条件 JSON，从不作为表达式求值。

## 导入与导出

- **导出**：设计页"导出 BPMN"导出当前画布（`<模型键>-draft.bpmn`）；版本列表导出所选版本规范化后的 XML（`<模型键>-v<版本>.bpmn`）。文件含 `qw` 配置。
- **导入**：只在 BPMN 设计器里做（不新增接口）。接受 `.bpmn`/`.xml`，以及版本列表导出的模型 JSON（取其中的树：不合规的 id 改成新 id 并提示，种子键名称换成当前语言的文字）。导入后画布未保存，校验立即显示，确认无误再存草稿或发布。BPMN 模型的版本列表不提供"导入 JSON"。
- **限制**：只支持上面的子集。其它 BPMN 工具（如 Camunda Modeler、Flowable、bpmn.io 在线 demo）导出的文件通常带表达式（`${...}`）、执行/任务监听器、`camunda:*`/`flowable:*` 等外来扩展，或带泳池、子流程，导入后发布会被拒并列出位置——需要在画布上删掉这些内容（或在原工具里去掉）再发布。"导入时自动剥离外来配置、只留图形"暂不做（⏸）。

## 实例详情的只读流程图

BPMN 版本的实例在详情页显示 bpmn-js 只读图（可平移缩放），走过的节点与路径标"已完成"、当前节点标"进行中"、未走的分支标"未经过"（灰）、驳回或撤销处标"在此结束"，与树形的进度树是同一份数据（汇合网关与分支内的连线由前端按配对补标）；树形版本仍显示进度树。移动端不显示流程图。

## bpmn.io 水印义务

bpmn-js 以 bpmn.io 许可发布（MIT 文本 + 水印条款）。本模板以及**基于本模板的任何项目**都必须遵守，具体要求以 bpmn.io 许可原文为准：

- 画布右下角的 bpmn.io 标志（设计器与只读图）必须**可见、不被遮挡、不被改动**：不写任何指向它的样式，画布右下角不放任何东西；属性面板停靠在画布旁边。用户主动打开、可关闭的临时对话框（选人、确认框）短暂盖住画布不算遮挡；常驻元素（面板、工具条、浮动按钮、应用水印）一律不得压住它；打印保留它。暗色主题下标志**下方**垫一块浅色底板（`--qw-logo-plate`），标志本身不动。
- 守卫：arch 检查 `scripts/arch/bpmn-watermark.mjs`（拦截以水印为目标的选择器与 `bpmn-embedded.css`），Playwright `wf-bpmn-canvas.spec.ts -g watermark`（亮/暗、面板打开、只读图与打印）。
- 许可按版本登记：`license-exceptions.json` 只放行 `bpmn-js@18.30.1`。任何升级（含补丁版本）都要先重读其 LICENSE，再在同一提交里改别名；条款变化或升大版本须重新评估兼容性与许可。`THIRD-PARTY-NOTICES.md` 收录许可全文。
- 不使用 `bpmn-js-properties-panel`（带入 Camunda/Zeebe 专属配置、FEEL 与 CodeMirror），属性面板是自写的 Vue 组件。

## 设计取舍

BPMN 只用于绘制和交换结构化流程，支持的图形编译为树形模型，运行时使用同一个树形引擎。表达式与监听器一律拒绝；回环、路由分支或任意汇合需要另行评估图引擎。
