# 用 AI 开发

本文写给用 AI 编程工具（Claude Code、Codex、Cursor、Copilot 等）在本模板上开发自己业务的人：模板为它们准备了什么、各工具读哪个文件、怎样加上项目自己的规则，以及什么时候算做完。

## 为什么适合 AI 编程

- **一份规则文件**：开发约定集中在仓库根目录的 [AGENTS.md](../AGENTS.md)，各工具的入口都指向它，不会出现几份互相矛盾的说明。细节链接到 `docs/` 下的技术文档，规则文件本身保持简短。
- **约定严格且可检查**：分层、命名、租户条件、数据权限、操作日志、多语言等都有固定写法，大部分由 `pnpm verify` 机器检查，AI 写错时立刻被拦下，而不是留到评审或上线后。
- **生成器优先**：标准 CRUD、树、主子表由[代码生成器](codegen.md)从表结构生成前后端代码与端到端测试，AI 只需在生成物上写业务扩展，少写、少错。
- **报错带改法**：检查失败时指出文件、原因和怎样修改，AI 可以照着改完再跑一遍。
- **项目地图**：`pnpm ai:map` 静态解析源码，生成 [docs/ai/project-map.md](ai/project-map.md)，列出领域与模块、表、接口与权限码、菜单路由名、字典码、系统参数、队列与定时任务、MCP 工具，AI 不必翻遍代码就知道项目里已有什么。代码变了重新运行即可；升级模板时这个文件冲突，直接重新生成。

## 各工具读哪个文件

| 工具        | 入口文件                          | 说明                                    |
| ----------- | --------------------------------- | --------------------------------------- |
| Claude Code | `CLAUDE.md`                       | 只有一行 `@AGENTS.md`，导入规则文件     |
| Codex       | `AGENTS.md`                       | 直接读取                                |
| Cursor      | `.cursor/rules/qiwu.mdc`          | 始终生效的规则，要求先读 `AGENTS.md`    |
| Copilot     | `.github/copilot-instructions.md` | 简短指引，要求先读 `AGENTS.md`          |
| 其他工具    | `AGENTS.md`                       | 支持 `AGENTS.md` 约定的工具大多直接读取 |

不要在入口文件里写规则正文，改约定只改 `AGENTS.md`（或下面的项目规则文件），各工具读到的内容就始终一致。

## 加上项目自己的规则

项目特有的约定（业务术语、领域划分、编码习惯、禁止事项）写在 `docs/project-rules.md`。模板不提供这个文件，所以升级模板时不会冲突。`AGENTS.md` 开头要求 AI 先读它，两者冲突时以它为准。

尽量不要直接改 `AGENTS.md`：它属于模板，升级时会随模板更新；项目的补充与例外都放进 `docs/project-rules.md`。

## 配方与技能

[docs/ai/recipes/](ai/recipes/) 是常见任务的分步配方：新增业务模块（生成器优先）、建表与迁移、权限与菜单、字典与系统参数、数据权限与手写 SQL、队列任务与定时任务、MCP 工具、智能助手的工具与技能、智能助手的扩展点（内置工具、上下文贡献者、审批审查者）、多语言词条、接口测试（含跨租户 404）。每篇按“适用场景 → 步骤（文件、命令）→ 完成检查 → 常见错误”组织，人和 AI 都可以照做。

Claude Code 另有技能入口 `.claude/skills/qiwu-*/SKILL.md`：每个技能只是指向对应配方的薄入口，在对话里按任务自动选用。其他工具直接让它读对应的配方即可。

## 完成线

AI 交付前必须跑通 `pnpm verify`（规则入口、lint、架构检查、项目地图是否过期、类型检查、i18n、原创性、许可，不连数据库）。改了模块、表、接口、权限、菜单、字典、参数、任务或 MCP 工具时，先运行 `pnpm ai:map` 更新项目地图，否则 `verify` 报它过期。改了接口时再跑对应的服务端用例，例如 `pnpm --filter @qiwu/server test erp-sale-order.e2e`（需要测试库，见[入门指南](getting-started.md#服务端测试)）。完整本地闸门 `pnpm ci:local` 耗时较长，由开发者在合并前决定何时跑。

`pnpm dev` 由开发者在终端交互运行，不要让 AI 启动常驻的开发服务器。

## 与 MCP 的区别

本文讲的是开发阶段：AI 帮你写代码。[MCP 智能体接入](mcp.md)是运行阶段的能力：已部署的系统让智能体以某个用户的身份调用业务工具，两者互不依赖。
