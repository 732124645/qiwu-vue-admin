# 配方：多语言词条

## 适用场景

任何会显示给用户的文字：页面标签、按钮、提示、菜单名、校验消息、字段名、服务端错误与通知。界面一律用词条键，`zh-CN` 与 `en-US` 两份同键；`.ts` / `.vue` 里不写中文字面量（种子与词条文件除外）。用户填写的业务内容按原文保存，不翻译。

## 步骤

1. **选对文件。** 项目词条放在本领域片段里，不改平台文案：

   | 内容                 | 文件                                                                                                  |
   | -------------------- | ----------------------------------------------------------------------------------------------------- |
   | 页面文字、菜单名     | `apps/web/src/locales/{zh-CN,en-US}/<domain>.<business>.json`                                         |
   | 字段名（校验与表头） | `packages/shared/src/i18n/{zh-CN,en-US}/modules/<domain>.<business>.json`，键 `field.<domain>.<prop>` |
   | 服务端错误与提示     | `apps/server/src/i18n/{zh-CN,en-US}/` 下项目自己的 `<domain>.<business>.json`                         |
   | 种子显示名           | `packages/shared/src/i18n/{zh-CN,en-US}/seed.json`，库里存 `seed.*` 键                                |

   `seed.json` 属于模板，没有项目自己的片段，项目的 `seed.*` 键加在里面，升级时可能冲突，见[升级模板版本](../../upgrade.md#3-常见冲突与处理)。

   带点的片段文件直接深度合并根对象，所以文件里写完整层级，不要再包一层文件名。参照 `apps/web/src/locales/zh-CN/demo.book.json` 与 `packages/shared/src/i18n/zh-CN/modules/demo.book.json`：

   ```json
   {
     "crm": { "customer": { "entity": "客户" } },
     "menu": { "crm": { "customer": "客户" } }
   }
   ```

2. **两种语言同时写。** en-US 文件保留同样的键，填人工校对的译文；生成器派生的英文要校对。
3. **页面里用键。** `t('crm.customer.entity')`；通用按钮与提示用已有的 `crud.*` 键，不复制。数据库里存词条键的字段（菜单名、种子名称）用 `tx(key)`，按语言存的 JSON（字典 `label_i18n`、参数 `name_i18n`）用 `localized(text, fallback)`。
4. **校验消息。** 校验写在共享 zod schema 里，消息是 `validation.*` 键，字段标签由 schema 的 `.register(fieldDomains, { domain: 'crm.customer' })` 对应到 `field.crm.customer.<prop>`（参照 `packages/shared/src/demo/book.schema.ts`）。服务端不建自己的 `validation.json` / `field.json`。
5. **服务端消息。** 业务错误在项目共享文件里定义 `ErrorDef`（`{ code, status, key }`，项目编码从 `E1xxx` 段起，平台的定义见 `packages/shared/src/common/error-codes.ts`），抛 `new BizError(def, params)`（`apps/server/src/core/http/biz-error.ts`）。键写成 `error.<domain>.<name>`，两种语言放进服务端片段（如 `{"error":{"crm":{"customerFrozen":"…"}}}`）；服务端按请求语言（`?lang=`、`Accept-Language`、用户语言）翻译。
6. **不要重复键。** 同一个键在 web、server、shared 里只定义一次，值相同也算重复。

## 完成检查

```sh
pnpm i18n:check
pnpm verify
```

`pnpm i18n:check` 检查两种语言同键、重复键、静态引用的键是否存在、业务源码里的中文字面量、种子显示名与通知模板的双语。它会打印 TODO 计数（en-US 空值与 `__todo.json`），发布前清零：`I18N_TODO_STRICT=1 pnpm i18n:check`。最后在界面里切换中英文，看页面、菜单、校验错误与导出的 Excel。

## 常见错误

- 只写了 zh-CN，en-US 缺键或留空：检查失败或计入 TODO。
- 在 `.vue` 模板或 `.ts` 里写中文提示：检查失败，改成词条键。
- 为了改一个项目文案去改平台的词条文件：升级模板时冲突，写进自己的领域片段。
- 片段文件外面再包一层文件名（`{"crm.customer": {...}}`）：键对不上。
- 动态拼接键（`t('crm.' + kind)`）：检查发现不了缺键，尽量写完整的键，或确认每个分支的键都存在。
- 对用户输入的名字调用 `tx()`：恰好像词条键的名字会被替换成译文。
