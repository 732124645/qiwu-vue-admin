# 后台智能体（智能助手）

“智能助手”从业务页面右侧的悬浮按钮打开：业务人员留在当前页面，用自然语言让智能体查数据、做汇总、按要求修改数据；需要外部信息时它联网搜索并阅读网页，修改前把“改哪条记录、每个字段的旧值 → 新值、依据哪些来源”交给人确认。也可以对列表里选中的多条记录批量执行一个技能（如“补齐客户信息”），结果进批次审批页逐条或一次确认。还可以把一个技能或一段提示词做成自动化，按时、在某个业务操作之后或手动在后台运行，结果进收件箱。

智能体只通过工具办事：工具就是各模块用 `@McpTool` 声明的方法（与 [MCP 智能体接入](mcp.md)同一个注册表与执行护栏），外加内置的联网工具、计划清单与反问。它不执行命令、不读写服务器文件、不操作浏览器。模型经兼容 OpenAI 的 Chat Completions 接口接入（官方 SDK `openai`，Apache-2.0），国内外常见的模型服务与本地 Ollama 都能用。

接口与类型见共享包 [agent.schema.ts](../packages/shared/src/platform/agent/agent.schema.ts)，服务端代码在 [apps/server/src/core/agent/](../apps/server/src/core/agent/)，页面在 [apps/web/src/views/platform/agent/](../apps/web/src/views/platform/agent/)。测试：开关 [agent-switch.e2e-spec.ts](../apps/server/test/e2e/agent-switch.e2e-spec.ts)，模型提供方 [agent-provider.e2e-spec.ts](../apps/server/test/e2e/agent-provider.e2e-spec.ts)，运行时、审批与限额 [agent-runtime.e2e-spec.ts](../apps/server/test/e2e/agent-runtime.e2e-spec.ts)，会话功能 [agent-threads.e2e-spec.ts](../apps/server/test/e2e/agent-threads.e2e-spec.ts)，联网工具与提示注入 [agent-web.e2e-spec.ts](../apps/server/test/e2e/agent-web.e2e-spec.ts)，外部 MCP [agent-mcp-client.e2e-spec.ts](../apps/server/test/e2e/agent-mcp-client.e2e-spec.ts)，技能 [agent-skills.e2e-spec.ts](../apps/server/test/e2e/agent-skills.e2e-spec.ts)，附件 [agent-attachments.e2e-spec.ts](../apps/server/test/e2e/agent-attachments.e2e-spec.ts)，批量执行 [agent-batch.e2e-spec.ts](../apps/server/test/e2e/agent-batch.e2e-spec.ts)，扩展点 [agent-builtins.e2e-spec.ts](../apps/server/test/e2e/agent-builtins.e2e-spec.ts)，配置方案 [agent-profile.e2e-spec.ts](../apps/server/test/e2e/agent-profile.e2e-spec.ts)，记忆 [agent-memory.e2e-spec.ts](../apps/server/test/e2e/agent-memory.e2e-spec.ts)，自动化 [agent-automation.e2e-spec.ts](../apps/server/test/e2e/agent-automation.e2e-spec.ts)，自动审查 [agent-review.e2e-spec.ts](../apps/server/test/e2e/agent-review.e2e-spec.ts)，诊断 [agent-diagnostics.e2e-spec.ts](../apps/server/test/e2e/agent-diagnostics.e2e-spec.ts)，通知设置 [agent-notify.e2e-spec.ts](../apps/server/test/e2e/agent-notify.e2e-spec.ts)。浏览器里走一遍：“补齐 → 审批 → 写入”见 [agent-chat.spec.ts](../apps/web/e2e/agent-chat.spec.ts)，“定时自动化 → 立即运行 → 运行历史与收件箱”见 [agent-automation.spec.ts](../apps/web/e2e/agent-automation.spec.ts)，“自动审查放行 / 交给人”见 [agent-review.spec.ts](../apps/web/e2e/agent-review.spec.ts)（三者都在测试里起一个兼容 OpenAI 的本地假模型，[agent-fake.ts](../apps/web/e2e/agent-fake.ts)）。

## 启用

| 开关                       | 位置                                         | 作用                                                                                                                                                                                            |
| -------------------------- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `APP_AGENT`                | 服务端环境变量，默认 `false`                 | 只在启动时读取，切换须全部实例重启。关闭时模块不加载：`/api/agent/*` 全部 404，不注册队列处理器，侧栏、角色授权树与租户套餐里不显示“智能体”菜单组，右侧悬浮入口也不出现                         |
| `agent.paused`（系统参数） | 系统参数页，默认 `false`，**只有 root 能改** | 暂停：为 `true` 时拒绝新的对话轮次与工具调用，正在运行的轮次在半秒内停下；改回 `false` 即恢复，暂停期间排队的消息与等并发名额的续跑随即补开（不必等别的轮次结束）。经参数缓存失效对所有实例生效 |

`APP_AGENT` 与 `APP_MCP` 互不依赖：两者共用工具注册表，但只开 `APP_AGENT` 时 `/api/mcp` 仍不存在。智能体的表始终由迁移创建，菜单与示例数据始终由种子写入（[agent.seed.ts](../apps/server/src/db/seeds/agent/agent.seed.ts)），打开开关不需要额外迁移；关着时菜单由 [menu-features.ts](../apps/server/src/core/auth/menu-features.ts) 隐藏。

打开后的第一步：

1. root 在“智能体 → 智能体设置 → 模型”里添加一个模型提供方（见下节）；没有可用模型时对话页提示联系管理员，输入框不可用。
2. 需要联网时在“联网搜索”页签添加一个搜索服务商。
3. 在“角色管理”给业务角色授权“智能助手”（`agent.chat.use`）；还要用技能管理、批量执行、用量、自动化页的再授权对应页面。root 看得到全部菜单。
4. 多租户时，把“智能体”菜单组勾进租户套餐，该租户的角色才能被授权；“智能体设置”是平台页，只属于默认租户。

菜单组“智能体”紧跟首页。聊天使用悬浮入口，授权与通知、分享旧链接仍保留隐藏路由；其余页面仍在管理菜单中：

| ---------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 智能助手   | `agent.chat.use`                                                                  | 悬浮聊天与隐藏会话路由；批次审批页挂在它下面（批量执行权限 `agent.batch.run`） |
| 技能管理   | `agent.skill.browse` / `create` / `modify` / `remove`，`agent.instruction.modify` | 个人与全租户技能、提示词模板、租户说明                                         |
| 智能体设置 | `agent.setting.browse` / `agent.setting.modify`（平台页，改动只有 root）          | 模型、联网搜索、外部 MCP、工具策略、平台技能、说明与限额、诊断（root）         |

| 自动化     | `agent.automation.use`，共享另需 `agent.automation.share`                         | 定时、业务事件或手动运行的技能与提示词，运行历史，见[自动化](#自动化)          |

## 配置模型

模型还需配置每百万 Token 的积分费率：普通输入、输出、缓存读取、缓存创建；空缓存费率沿用普通输入，明确填写 0 才代表免费。费率与预算用最多 6 位小数的十进制字符串保存，按百万分之一积分做整数计算，每次调用合计后只向上舍入一次。推理 Token 属于输出细分，不再次加到输出总数扣费；供应商报的推理多于输出时说明输出没含推理，按输出 + 推理计。配了费率的模型每次调用都会计积分：配了缓存读取或写入费率、供应商却没报对应细分（或细分超过输入）时，全部输入按输入 / 缓存读取 / 缓存写入里最高的费率计；`total_tokens` 与输入加输出不一致时以输入 + 输出为准；仍无法计价时按这次调用的估算计（见下文用量）。没有费率的模型（包括升级前已有的模型）照常可用，设置页标为“未配置费率”；它的调用记为未计价，不计入积分额度，也不当成免费，只在用量页的完整性提示里列出。审查模型、记忆提炼与深度研究同样不因缺少费率停用。

模型思考的能力声明与默认行为分开：可选提供方默认、明确关闭或受支持的强度；标准兼容协议按模型支持的 reasoning_effort 发送，明确关闭发送 none；部分兼容服务不认识 none 会回 HTTP 400，此时调用报“模型服务不接受关闭思考”，不自动改发其他值重试，应换思考强度或把默认改为提供方默认 / vLLM 开关。vLLM 协议仅映射 enable_thinking 开关，界面只表示开/关，不伪装低中高等级。取消能力声明不等于向供应商发送关闭参数。

“智能体设置 → 模型”里每个提供方填：名称、接口地址（base URL，到 `/v1` 这一级，系统在后面接 `/chat/completions`）、密钥、可用模型列表，可设为默认。每个模型可标注：显示名、是否支持推理强度（对话里可选低 / 中 / 高，发 `reasoning_effort`）、是否能看图片（附件里的图片只交给这类模型）、是否作为“快速”选项、上下文窗口（默认 64000 token，决定何时自动压缩）、是否是图片模型（标了的第一个模型用来生成图片，见[图表、图片与导出](#图表图片与导出)）。

常见服务的接口地址（模型名以各家文档为准，密钥在各家控制台申请）：

| 服务                   | 接口地址                                            | 模型名示例        |
| ---------------------- | --------------------------------------------------- | ----------------- |
| DeepSeek               | `https://api.deepseek.com/v1`                       | `deepseek-chat`   |
| 通义千问（阿里云百炼） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`       |
| Kimi（月之暗面）       | `https://api.moonshot.cn/v1`                        | `moonshot-v1-32k` |
| 智谱                   | `https://open.bigmodel.cn/api/paas/v4`              | `glm-4-plus`      |
| Ollama（本机或内网）   | `http://127.0.0.1:11434/v1`                         | `qwen2.5:14b`     |
| OpenAI                 | `https://api.openai.com/v1`                         | `gpt-4.1-mini`    |

智能体依赖模型的工具调用（function calling）能力，请选支持它的模型。不需要密钥的本地服务（Ollama）密钥留空。

- 密钥只写不读：用 `APP_SECRET` 派生的独立密钥加密存库，接口只返回 `hasKey`；保存时不填密钥即保留原密钥，但改了接口地址必须重新填（原密钥不会被发到新地址）。`APP_SECRET` 变更后旧密钥打不开，须重新填写。
- 会话可以从已配置的提供方与模型里选；没选时用默认提供方的第一个模型。
- 上游的报错正文不外传（可能回显密钥片段或提示词），页面只看到“模型服务调用失败”与简短原因（超时、HTTP 状态、网络）。模型请求不自动重发，避免在接收状态不明时重复付费；用户明确的新尝试单独登记。

## 联网搜索

内置两个只读工具：

- `web.search`：经配置的搜索服务商搜索公网，先支持 [博查](https://open.bochaai.com/)（国内）与 [Tavily](https://tavily.com/)（海外）。在“联网搜索”页签添加服务商（类型、名称、密钥，可设默认），密钥同样加密存库、只写不读；没有配置时不提供这个工具。
- `web.fetch`：读取一个网页（HTML 转成纯文本，也接受纯文本与 JSON），**只能读本轮 `web.search` 返回过的链接、用户消息里给出的链接，或白名单网站的链接**。

两个系统参数（root，在“联网搜索”页签或系统参数页修改）：

| 参数                        | 默认   | 作用                                                                                   |
| --------------------------- | ------ | -------------------------------------------------------------------------------------- |
| `agent.web.mode`            | `live` | `live` 联网；`off` 不提供任何联网工具                                                  |
| `agent.web.allowed_domains` | 空     | 逗号分隔的域名（含子域名），`web.fetch` 可以直接读；空表示只读搜索结果与用户给出的链接 |

## 外部 MCP 服务器

“智能体设置 → 外部 MCP”可以接入本系统以外的 MCP 服务器（Streamable HTTP），让智能体调用它们的工具。本系统自己的工具仍在进程内调用，不经 MCP。

- **鉴权方式**：`none`；`header`（每次请求带一个请求头令牌，如 `Authorization: Bearer …`，不能设置传输自用的请求头）；`oauth`（OAuth 客户端凭据模式：令牌地址、客户端 id、客户端密钥、可选范围，令牌缓存到过期前）。凭据加密存库、只写不读；改了地址或鉴权方式必须重新填写凭据。
- **地址**：默认只能是公网地址，连接时按解析结果再查一遍（防 DNS 重绑定）。指向内网（如 `http://10.0.0.5/mcp`）须 **root 显式勾选“允许内网地址”**。
- **同步工具**：点“同步”连接服务器并列出其工具。新工具默认**停用**、策略为 `ask`；服务器上消失的工具自动停用。管理员逐个启用并设审批策略；服务器声明的“只读”不可信，只有管理员显式设为 `auto` 的外部工具才会直接执行，其余一律当作写入、调用前要人确认（`ask` 的在自动审查模式下先交审查模型，见[自动审查](#自动审查)；`human` 的只能由人确认）。外部工具每次都问，不能“本会话内不再询问”。
- 外部工具在模型那里叫 `ext.<服务器名>.<工具名>`；它的描述、参数说明与返回内容都当作不可信外部内容。服务器在调用中途请求用户补充信息（MCP elicitation）时，对话页显示一张表单卡片，最多等 10 分钟。
- 每次调用记操作日志（同下文的审计）。

## 工具策略

工具列表和审批卡优先显示当前语言的工具名称与用途，工具标识保留在辅助文字中，便于管理员核对。所需权限显示已有菜单与动作名称；未知第三方工具使用其提供的原文，执行时仍使用原始标识与权限码。配置方案可从本人可用工具中选择，也可输入其他工具标识；留空表示不限制工具，执行权限与审批策略仍逐次检查。

“智能体设置 → 工具策略”列出本系统的全部工具（`@McpTool` 工具、`web.search` / `web.fetch` 与来源为“内置”的智能体内置工具，如 `plan.update`、`ask.user`、`skill.load`），每个一个审批策略，对所有租户生效：

| 策略    | 含义                                                                                                                                        |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`  | 自动执行（只读工具的默认）                                                                                                                  |
| `ask`   | 需确认（写入工具的默认）：每次询问模式下停下等发起人，自动审查模式下先交审查模型；只读工具设为 `ask` 时在任何模式下都停下等发起人，从不送审 |
| `human` | 仅人工确认：只能由发起人在卡片上逐次确认，从不送审，也不能“本会话内不再询问”（高风险写入的默认）                                            |
| `deny`  | 不提供给智能体                                                                                                                              |

写入工具只能是 `ask`、`human` 或 `deny`，设 `auto` 被拒（400；库里即使被改成 `auto` 也按默认执行）；只读工具只能是 `auto`、`ask` 或 `deny`（400；库里被改成别的也按 `auto`）。读取默认不弹卡；root 显式设为 `ask` 的读取（如花钱的生成图片）在只读与计划模式下也停下问人，可以“本会话内不再询问”，从不交给审查模型。“恢复默认”回到默认值：`@McpTool` 声明了 `highRisk: true`（删除记录、批量修改、对外发送、涉及金额）的写入默认 `human`，其余写入默认 `ask`；`humanOnly` 的内置工具除 `deny` 外总按 `human`。在“MCP 工具”页整体停用的工具，智能体同样用不了；内置工具的启停就在本页（只有 root 能改）。

需要每次本人确认的业务写工具声明 `perCallConfirmation: true`，同时提供真实 `preview` 与 `confirmationRevision: '1'`。它们不接受会话放行、自动审查、自动化预先同意或批量同意；只能在助手单张确认卡上由本人点击。直接 MCP / PAT 没有这份服务端凭据，不能执行；未声明此能力的工具保持原策略。

`confirmationRevision` 是服务端工具契约版本，须在全部 API 和 worker 实例保持一致。修改 JSON Schema 不能表达的 refine/superRefine 校验、转换或默认值语义时必须递增。框架会自动比较 JSON 结构约束，但不会自动发现未声明版本变化的 opaque 代码。逐次确认工具的 Schema 不采样保留动态 default 注解，默认语义由这个明确版本负责；普通工具的导出不变。确认后参数、契约、预览或权限事实改变会重新等待确认。实际业务仍须在事务锁内核对 `ToolExecutionContext.confirmation.preview` 的模型版本、附件与引用，不能把先前的预览当成业务锁。

## 自动审查

自动审查让写入不必每次都等人点确认，由另一个模型（审查模型）先看一遍：

1. root 在系统参数 `agent.review.model` 里填审查用的模型，格式 `<提供方 id>:<模型 id>`（提供方须已启用、模型在其列表里）。没填时会话模式里没有“自动审查”，接口也拒绝选它（400）。
2. 发起人把会话模式切到“自动审查”。不需要逐个工具开启：策略为 `ask` 的写入（默认）都会先送审。

之后每个本该弹卡的写入先交审查模型判断：

- **放行**：直接执行，审批卡记为“已自动审查通过”并附理由；
- **驳回**：不执行，也不替人拒绝：卡片停下等发起人，标明“自动审查驳回”与理由，发起人仍可确认或拒绝（拒绝时模型被告知不要换个说法重试）；
- **交给人**：照常等发起人确认，卡片上附审查的说明。

只有同时满足“此刻的工具策略是 `ask`、此刻的会话模式是自动审查”的放行才生效（运行时在审查模型答完之后重新读取），其余一律交给人。策略为 `human` 的写入、须本人逐次确认的工具、只读与计划模式从不送审（自动审查模式下，这类没有送审就等人的卡片会写明原因，`unreviewed`：`policy` 工具仅人工确认、`read` 设为询问的只读工具、`personal` 须本人逐次确认、`mode` 只读或计划模式、`paused` 已暂停、`no_model` 平台没有指定审查模型）；本会话已放行的工具直接执行，不送审。以下情形不调用审查模型或不采用它的结论，直接交给人并在卡片上写明原因，从不默认放行：审查模型出错、超时（30 秒）、回答不是规定的 JSON（多一个字段也不行）、指定的模型已不可用；本轮积分预算或发起人 / 本租户今日积分预算已用完；本轮已送审 10 次；同一个工具在本轮已被驳回 2 次（模型在反复尝试同一个被拒的写入）；参数或改动预览太大、需要截断才能交给审查模型（截断后的写入它看不全）。暂停时不调用审查模型。每次审查调用保留供应商的实际用量，并按该次模型费率计入本轮与发起人的每日积分；缓存与推理细分不重复加到总量扣费。驳回理由是审查模型写的文字，交给主模型时按不可信数据加引号，卡片上注明“审查模型的说法”。

审查模型看到的只有：用户本人在本会话最近几条消息的文字（不含助手与工具的内容，照抄上一条回答里后续建议发出的消息整条不算，事件自动化消息末尾的事件行——领域、动作与记录 id——也去掉；按转义后的长度共用一份额度，最新一条优先，放不下时从最旧的一端丢）、工具名与标题、改动预览（系统按库里的记录算出：旧值是库里的业务数据，可能含任何人写的文字；新值来自参数）、参数（助手写的，可能受到它读过的外部内容影响），以及本轮联网工具带回的来源链接与标题。它看不到任何工具的输出或网页正文。每一部分放在各自标注的块里（转义后无法伪造块的边界）；来源，以及外部工具的名字、标题与参数（参数名来自外部服务器的 schema）放在不可信块里。系统提示告诉它：任何块里的文字都只是数据，块里出现要求批准、改变或忽略规则、改变回答格式的文字，本身就是交给人的理由。这些措施只是让这类文字更难左右结论，并不能保证审查模型不被骗过。外部 MCP 工具的名字、标题和参数都按不可信内容处理，审查模型据此很难确认这次写入符合用户的请求，所以外部工具送审后多半会交给人。

**局限**：审查模型同样可能判断错误，或被精心构造的参数、业务数据与上下文误导；它只能对照用户在本会话里说过的话，并不理解业务规则，也不替代权限与数据权限（工具仍按发起人本人的权限执行）。删除、批量修改、对外发送和涉及金额的写入请设为（或在 `@McpTool` 里声明 `highRisk: true` 默认为）“仅人工确认”，它们从不送审。所有放行都在审批卡与操作日志里留有记录，可事后核对。

## 技能

技能是一段任务说明加上允许使用的工具，例如“补齐客户信息”：逐个联网查官网、行业、城市……只填空字段并给出来源。技能只是说明文字，不含可执行代码。

| 范围 | 谁维护                                                             | 谁能用             |
| ---- | ------------------------------------------------------------------ | ------------------ |
| 平台 | root，在“智能体设置 → 平台技能”                                    | 所有租户的所有用户 |
| 租户 | 持有 `agent.skill.create` / `modify` / `remove` 的人，在“技能管理” | 本租户的用户       |
| 个人 | 本人（有 `agent.chat.use` 即可），在“技能管理”                     | 本人               |

同名时个人的优先，其次租户，最后平台。

- **渐进加载**：模型平时只看到可用技能的名称与描述，判断要用时调用内置工具 `skill.load` 取正文。
- **显式调用**：在输入框打 `$` 选技能（或 `/skills`），本轮直接载入该技能的正文；技能列了工具时，本轮只提供这些工具（内置工具总在）。
- **从会话生成**：`POST /api/agent/skills/from-thread/:id` 让模型根据一次会话起草一个个人技能，保存为停用状态，检查后在技能页启用。
- **导入导出**：技能页可导入、导出 `SKILL.md`。格式（解析见 [skill-md.ts](../apps/server/src/core/agent/skills/skill-md.ts)）：开头用 `---` 包起来的前言，只允许 `name`、`description`（写“什么时候用”）与可选的 `tools`，之后是正文。名称由字母、数字（含中文）与 `-` 组成，最长 64 个字符。

```markdown
---
name: 补齐客户信息
description: '补齐客户资料：联网查官网、行业、城市、规模、电话、地址、简介，只填空字段并给出来源'
tools: [web.search, web.fetch, demo.customer.get, demo.customer.update, ask.user]
---

为选中的客户补齐资料。逐个处理：

1. 用 demo.customer.get 读出现有资料，记下哪些字段为空。
2. 用 web.search 按客户全称搜索，再用 web.fetch 阅读官网或权威页面核实。
3. 搜到多家名字相近的公司时，用 ask.user 让用户选，不要猜。
4. 调用 demo.customer.update 只填空字段；查不到的留空，不要编造。
5. 最后总结补了哪些字段、每个值来自哪个链接。
```

`tools` 也可以写成多行的 `- 项` 列表。

## 说明、语气与提示词模板

- **说明**拼在系统提示里，依次是：平台说明（系统参数 `agent.instructions`，root）→ 租户说明（“技能管理”页，需 `agent.instruction.modify`）→ 个人说明（每个用户自己写，如“回答用表格”）。
- **语气**是个人预设：默认、简洁、详细、亲切、正式（与页面上的选项一致）。
- **提示词模板**：个人或全租户（后者需 `agent.skill.modify`）的常用提问，输入框里用 `/prompts` 插入。

## 配置方案

配置方案是一组命名的设置：模型与推理强度、会话模式、允许的工具清单和一段额外说明。对话页头部的“配置方案”按钮打开列表，可以新增、编辑、删除；方案分个人的和全租户共用的（后者的增改删需要 `agent.skill.modify`），别人的个人方案看不到，操作一律 404。每个范围可以设一个默认。

- **新建会话时**在头部选一个方案（默认选中本人的默认方案，没有时用全租户默认；选“不用方案”即 `profileId: null`，也不取默认）：方案的模型、推理强度和会话模式带进会话，请求里另给的字段优先——模式也一样，只有请求没给时才取方案的。模式只能选平台此刻提供的（例如没指定审查模型时不能选“自动审查”），保存时不允许的返回 400，建会话时已不允许的退回“询问”。
- **全租户方案的模式只能是“只读”“计划”或“每次询问”**：“自动审查”是让审查模型替本人同意写入，只能由本人在个人方案或会话里选，别人建的方案不能替本人选。
- 工具清单里的名字必须是存在的工具（本系统、联网、内置或本人此刻能用的外部工具），否则 400；每个范围最多 50 个方案。
- **运行时**工具清单与 `$技能` 的工具清单同一条规则：给了清单就只提供清单里的工具，只读的内置工具总在，写入类内置工具（如 `memory.save`）必须列在清单里；技能和方案都给了清单时两边都要列着。额外说明作为用户角色的上下文放进每次请求（不进系统提示）。
- 方案被删除、被改成别人的个人方案或在别的租户时，用着它的会话退回默认行为（不限制工具、不加说明），不报错。会话里也可以换用或去掉方案（`PATCH /api/agent/threads/:id` 的 `profileId`）。

接口：`GET|POST /api/agent/profiles`、`PUT|DELETE /api/agent/profiles/:id`（`agent.chat.use`）。表单里的候选工具来自 `GET /api/agent/my-tools`（`agent.chat.use`）：本人此刻能触达的本系统工具、联网工具、内置工具和已启用的外部 MCP 工具，平台停用或策略为 deny 的不列；它属于智能体模块，`APP_MCP` 关着时同样可用。

## 记忆

每人一个记忆库（内容、来源会话、时间），只属于本人。对话页头部的“我的记忆”按钮打开列表：可以搜索、新增、编辑、删除，“全部忘记”需要输入当前密码（与锁屏校验共用试错计数）。删除是物理删除。

- **写入**：用户明确说“记住……”时智能体调用内置工具 `memory.save`。它只能由人确认：停下等卡片上的确认（卡片上就是要记住的内容；不能“本会话内不再询问”），管理员设的策略除 `deny` 外都按“仅人工确认”处理，从不交给审批审查者放行；执行时再看一次会话是否仍开着记忆。保存前用 `core/redact` 的 `maskSecrets` 遮蔽：`key=value` 与“密码是 …”“pwd123456”这类说法（引号里的整段）、PEM 块、JWT、`sk-` / `ghp_` 等已知前缀的令牌（前缀后 20 位以上且含数字）与 AWS 密钥 ID、18 位身份证号、通过 Luhn 校验的 13–19 位卡号、大陆手机号和像密钥的长串；换行压成空格。同样的内容只存一条，每人最多 200 条——满了智能体会请用户先去清理。
- 记忆内容和对话消息正文在操作日志与接口日志里都以 `***` 遮蔽，不留原文。
- **遮蔽不是万能的**：规则只认常见的形式。名称后跟冒号或等号时值总被遮住；跟“是 / is”或紧贴名称时只遮像密钥的值（ASCII、含数字），所以“忘记密码后无法登录”“the token is valid”这类句子保持原样。已知会误遮的：11 位的工单号（像手机号）、碰巧通过 Luhn 校验的订单号、UUID 与提交哈希（像密钥的长串）。已知会漏掉的：带区号的手机号写法、座机号、IBAN、统一社会信用代码，以及没有名称提示、又不像密钥的口令。请不要让智能体记住任何敏感信息，记忆可以在“我的记忆”里随时查看和删除。
- **后台提炼**：系统参数 `agent.memory.extract`（root，默认 `false`）打开后，每 10 分钟从空闲 30 分钟以上、7 天内活动过的会话里提炼。只读用户自己发出的消息：回答、工具结果（网页、外部 MCP 的内容）、附件和照抄后续建议发出的消息都不进提炼输入。关了记忆的会话、临时会话、子智能体与自动化、批量开的会话不提炼；每个会话记下读到的位置（Redis，分叉出的会话沿用源会话的位置），同一段不提炼第二次，Redis 数据丢了时靠“同样的内容只存一条”兜底；记忆已满时不调模型；每人每天最多调用模型 20 次、由提炼加 10 条；调用模型受暂停与每日积分预算约束并记进用量。
- **使用**：会话开着记忆（默认开，头部“使用记忆”开关可逐会话关掉）时，按最新一条消息挑最相关的若干条（命中的词数，再按最近使用与新建时间），作为用户角色的上下文“关于你的记忆”放进本轮（每条写成一个 JSON 字符串）；条数上限是系统参数 `agent.memory.per_turn`（root，默认 `5`，`0` 为不用）。临时会话不读也不写记忆；`/status` 估算上下文时只读不写。

接口：`GET|POST /api/agent/memories`、`PUT|DELETE /api/agent/memories/:id`、`POST /api/agent/memories/forget-all`（`agent.chat.use`）。

## 限额、暂停与用量

系统参数（root）：

| 参数                                  | 默认    | 作用                                             |
| ------------------------------------- | ------- | ------------------------------------------------ |
| `agent.limit.turn_steps`              | `20`    | 每轮最多步数（每请求一次模型算一步）             |
| `agent.limit.turn_seconds`            | `300`   | 每轮最长秒数（按每次运行计，等人确认的时间不算） |
| `agent.limit.turn_credits`            | `0`     | 每轮累计积分预算，0 不限额                       |
| `agent.limit.user_daily_credits`      | `0`     | 每用户每日积分预算（UTC 日），0 不限额           |
| `agent.limit.tenant_daily_credits`    | `0`     | 每租户每日积分预算（UTC 日），0 不限额           |
| `agent.limit.user_concurrent_turns`   | `2`     | 每用户同时运行的轮次数（等人确认的轮次不算）     |
| `agent.limit.research_steps`          | `60`    | 研究模式每轮最多步数，见[深度研究](#深度研究)    |
| `agent.limit.research_seconds`        | `1200`  | 研究模式每轮最长秒数                             |
| `agent.paused`                        | `false` | 暂停，见[启用](#启用)                            |
| `agent.review.model`                  | 空      | 审查模型，见[自动审查](#自动审查)                |
| `agent.memory.extract`                | `false` | 后台提炼记忆，见[记忆](#记忆)                    |
| `agent.memory.per_turn`               | `5`     | 每轮放进几条记忆，见[记忆](#记忆)                |
| `agent.limit.automations_per_user`    | `20`    | 每人最多几条自动化，见[自动化](#自动化)          |
| `agent.limit.automation_runs_per_day` | `50`    | 每条自动化每天最多运行几次，见[自动化](#自动化)  |

超限时这一轮停下，并在对话里说明是哪个上限；超出并发时新消息被拒（429）。用量按用户、租户、模型与日期记账，“智能体用量”页按日、用户或模型汇总当前租户的积分、调用次数与真实 Token 明细；输入框旁的 `/status` 显示本会话的上下文用量、本轮与今日用量和上限。

积分预算按已发生并记录的消费在每次模型调用前检查，达到后不再发起后续调用，在途调用可能越过阈值。0 是明确不限额，步数、时间、并发和模型上下文容量仍各自有效。原始 Token 仅作计量和上下文观测，不直接作为消费额度。

升级库里的旧 Token 预算参数仅供历史与回退保留，不再参与运行时额度；不能把旧 Token 数直接换成积分。旧模型不补费率也能继续调用（记为未计价）；三项积分预算默认 0 表示不限额，三项都为 0 时设置页的“使用规则与额度”和“开始使用”引导会提示“当前没有积分额度上限”，root 可直接跳去设置。

用量按提供方和精确模型标识区分：相同模型名在不同提供方、大小写不同的标识不会混账。每次调用保留实际用量与当次费率，调价不重算历史；分页明细可查看输入、输出、缓存、推理和供应商的数字明细。缺失字段显示未知，不是 0。升级前没有细分/费率的旧记录单独标记，不补造历史积分；模型没有费率时调用不计入积分、也不受积分额度限制；模型有费率但这次用量未知（模型服务不报告用量，或调用在结束前被停止、超时、出错、丢锁）时按保守估算计积分并计入三项额度：输入按本次请求内容估算（UTF-8 字节数 / 3，图片按固定数），输出按已流出的回答、推理与工具参数估算，什么都没流出时输出记 0；估算同样遵守上面的缓存规则（没有缓存细分，输入按三项里最高的费率计）；明细标为“估算”，估算不计入 Token 统计。两种情况在用量页的完整性提示里分别列出。图片的显式单张后备积分只在无可计价 Token 时使用，不与 Token 费用双收；没配单张积分的图片模型成功但没报用量时，按提示词估算加固定的 6240 个输出 Token（常见按 Token 计费的图片模型最高一档）计。“未计价”只指模型没配费率的调用。

## 诊断

“智能体设置 → 诊断”只给 root（多租户关着也一样）：模型与搜索服务商的启用与是否有密钥（不显示密钥）、外部 MCP 服务器的连接状态与最近错误、轮次队列的积压（等待 / 执行中 / 失败 / 延迟）、所有租户里运行中、等人处理与今天（UTC）失败的轮次数、最近 20 个失败轮次（编号、租户、原因码与截短的说明，不含会话内容），以及孤儿轮次清理的最近一次时间与累计“重新入队 / 置为失败”次数。

每个模型提供方、搜索服务商与外部 MCP 服务器都能做一次连通测试：模型做一次极短的补全（不重试，15 秒超时），搜索搜一次只要一条，MCP 只连接并列出工具（不同步、不改状态）。结果是用时，失败时只有原因码（`timeout`、`network`、`auth`、`http_<状态码>`…，页面配了说明），从不回显密钥或对方的报错正文。测试记操作日志，每个测试每个来源地址每分钟最多 10 次。

## 断线、刷新与发版恢复

浏览器断线不会取消已经接收的任务。重新连上后，按条目版本和字符偏移补拉已保存内容；服务端约每 200ms 批量形成检查点，先提交数据库再广播，因此已显示的前缀可以恢复。模型连接中断后恢复的是任务状态，当前步骤可能重新生成，不承诺原连接从某个 Token 继续，也不承诺没有额外的实际上游调用费用。

新版前端为草稿和每次发送保留稳定标识。未收到确认响应时，重连只查询接收凭据；明确重试复用原标识，已经接收、撤回或删除的意图不能再次执行。同一标识对应不同内容会被拒绝。浏览器长期或会话存储只保留按用户、租户隔离的少量标识，不保存消息正文；整页刷新不保证保留未发送草稿。

模型请求发出前先登记持久调用，明细区区分计量中、已完成与中断未知；结算时在同一事务归集日账、本轮和父轮。真实回执晚到只补同一次调用，保留原费率，调用次数不再增加；没有回执的用量在 Token 统计里保持未知、不补成 0；有费率时积分按上面的估算计（调用发出前先记一份只含输入的估算，进程中途崩溃后的接管结算也按它计），真实回执晚到时以真实用量重算。有限预算下，过期尚未归集的调用会让下一次调用暂时等待其结算。

写入或付费图片没有得到可信结果时，后续副作用硬暂停，会话放行和自动化预授权不能绕过。本地工作尚未结束时不能解除暂停；外部非幂等操作须到对方系统核对实际结束和效果。本人按当前风险版本确认后，只允许后续操作，不自动重跑旧轮次或过期队列。关联自动化会停用并撤销预授权，需要另行重新配置。分叉、撤回和删除也须先停止活跃任务并处理待核对结果。

正常发版先暂停取新任务、有界等待并保存、取消未完请求，再关闭队列和连接；强杀后的接管依赖数据库记录和租约检测，不能承诺固定恢复秒数。必须保留数据库、Redis 和 APP_SECRET。首次从没有检查点的旧版本升级，应先暂停新任务并排空或人工核对旧工作，再停旧 worker、迁移和启动新版；不能追溯恢复旧版本从未保存的片段。混合旧 worker 或直接回滚到不理解恢复闸的版本不能作为安全恢复办法。

## 聊天面板

右侧悬浮入口在当前业务页打开聊天，业务地址与筛选保持；桌面可收起或展开，手机全宽。关闭后重新打开保留当前会话与草稿，只暂停前端补读，后台正在执行的轮次继续；停止任务仍使用明确的停止按钮。权限、身份或租户变化会清理面板状态。独立会话页面继续用于通知、分享与旧链接。

聊天标题栏的工作面板默认收起，桌面并排阅读，窄屏为抽屉。任务汇总最新计划、工具状态与子任务；来源只读取当前对话已授权引用并给安全链接，不请求网页图标或元数据；产物复用报告、图表和图片预览。换会话立即清空旧预览，分享视图仍保留只读与文件权限边界，审批只在原确认卡片办理。

回答支持展开阅读、Markdown 原文切换、代码块独立复制与折行、下载原文。标准 GFM Token 转成安全文字 VNode，支持嵌套列表、任务清单、表格与懒代码高亮；HTML 作为文字，外部 Markdown 图片只给显式链接，不自动加载，也不执行模型提供的脚本。过长或过深内容保留完整原文退化显示。

- **会话**：左侧列表可新建、搜索（标题与消息全文）、改名、置顶、归档 / 恢复、删除，按“全部 / 进行中 / 未读 / 置顶”筛选；第一条消息自动生成标题。临时会话不进列表，离开或闲置 24 小时后清理安全的已停止会话正文；仍在执行或待本人核对的会话保留，永久投递标识和计量审计也保留。
- **分叉与撤回**：从任意消息分叉出新会话（复制到该条为止的内容）；“编辑后重发”最后一条消息也是分叉；“撤回”删除最后一轮及其条目——已经执行的写入**不会回滚**。
- **分享与导出**：分享生成只读链接，只有同租户的人能打开，查看者只看得到自己有权调用的工具的结果；导出为 Markdown；单条消息可复制、点赞点踩并留言。
- **会话模式**（每个会话一个，`approvalMode`，`/approvals`）：`read_only` 只读（只提供只读工具）、`plan` 计划（同样只读，智能体最后提交一张方案卡，你批准后才执行，见[计划模式](#计划模式)）、`ask` 每次询问（默认，每次写入都确认）、`auto_review` 自动审查（平台指定了审查模型时才有，见[自动审查](#自动审查)）。读取工具默认在任何模式下都不弹卡（root 设为 `ask` 的除外）。审批卡片列出工具、目标记录、逐字段的旧值 → 新值与本轮读过的来源，可以“确认执行”、“本会话内此工具不再询问”（`approve_session`，只在卡片提供时，`sessionAllow`）、拒绝（可写一句说明，智能体收到后不再照原样重试）或取消本轮。缺权限、只读模式或平台策略挡住的调用显示一张说明缺什么的卡片。
- **本会话内不再询问**：按工具名记（设为 `ask` 的只读工具也可以，只读与计划模式下同样有效），之后这个工具在本会话里对任何记录都直接执行，卡片记为“本会话已放行”（`allowedBy: 'session'`），不送审。会话的 `allowedTools` 列出已放行的工具，`DELETE /api/agent/threads/:id/allowed-tools/:tool` 撤销一个（只有本人；运行中的轮次在下一次调用时就按撤销处理）。记下之前按工具此刻的策略再核对：卡片出来之后 root 已把它改成 `human`、`deny` 或停用的，只同意这一次、不记放行；执行时也每次重新核对此刻的策略、模式与放行列表。切换模式不清除放行；撤回一轮时去掉这一轮记下的放行；分叉不带过去；分享出去的只读视图里 `allowedTools` 总是空的。须本人逐次确认的工具、`humanOnly` 与策略为 `human` 的工具不能放行（400）。外部 MCP 工具也从不放行（400，库里已有的放行记录不算）：`ext.<服务器>.<工具>` 这个名字不是稳定身份（规整后撞名、改派后缀、同名服务器重建都可能指向别的操作），外部工具也常是能做任意操作的接口，所以它们每次都问。
- **计划**：多步任务里智能体用内置工具 `plan.update` 维护清单，面板实时显示进度；同一时刻至多一步“进行中”，两步同时进行中的调用作为工具错误退回给模型。计划模式的方案卡见[计划模式](#计划模式)。
- **反问**：智能体不确定时用内置工具 `ask.user` 提 1–4 个问题，每题 2–4 个选项（单选或多选）加“其他”自由填写；本轮停下等回答，也可以选择不回答。
- **附件**：消息可附带最多 10 个已上传到文件存储、发送人有权读取的文件。文本类（txt、md、csv、json、log）读入前 200 KB，xlsx 取第一张表转成 CSV，png / jpeg / webp / gif（5 MB 以内）交给能看图片的模型，其余类型只告诉模型文件名。
- **运行中发消息**：默认“追加到本轮”，排在当前步骤之后处理，用来改方向；也可选“排到下一轮”。本轮正停在方案卡上时，发消息等于带这条消息“继续完善”（见[计划模式](#计划模式)）。本轮正停在审批卡上时，发消息（追加或排队都一样）等于“拒绝并附这条说明”：这一轮所有待定的审批卡（包括须本人逐次确认的）记为拒绝、备注是这条消息，同一步里还没轮到出卡、会停下问人的调用（写入，以及设为 `ask` 的只读工具）也一并记为拒绝（不再一张张弹出），策略为 `auto` 的读取照常执行，消息并入本轮，本轮立即继续（还有待回答的提问时等提问答完）；批量任务的会话照旧。随时可以点“停止”。
- **上下文压缩**：用量接近模型上下文窗口的 80% 时自动把较早的对话压成摘要继续，对话里显示一条分隔标记；也可手动 `/compact`。输入框旁的圆环显示上下文用量。
- **斜杠命令**：`/new` 新会话、`/compact` 压缩、`/model` 切换模型、`/approvals` 会话模式、`/plan` 计划模式、`/skills` 选技能、`/prompts` 提示词模板、`/mcp` 打开外部 MCP 设置、`/status` 用量与状态、`/clear` 清空并新建。
- **其他**：支持的模型显示可折叠的“思考”摘要；回答后给出 0–3 条后续建议；回答里引用的网页列在末尾。一轮停下等你确认或回答，以及耗时超过 30 秒的一轮完成时，发站内信提醒。
- **通知设置**：头部的铃铛按钮里，每类提醒（耗时较长的一轮完成、等确认或回答、自动化运行结果）可以另开“同时发邮件”，默认都关。站内信总会收到，手机端通过站内信同步；邮件走现有邮件通道（模板 `agent.turn.completed` / `agent.turn.waiting` / `agent.automation.result`，在邮件模板里可改），发到个人资料里的邮箱，没填邮箱的只收站内信。同一轮多次停下等你时，站内信每次都发，邮件只发第一封。设置按用户存在个人偏好里（`GET|PUT /api/agent/notify-settings`）。提醒只写通用文字与会话路由（`/agent/chat?thread=<id>`），不带会话标题；早先装好的模板正文里的 `{title}` 显示为 `#<会话编号>`。平台人员进入其他租户时，这些个人设置（记忆、配置方案、通知设置、自动化）按本人租户处理。
- **快捷键与新窗口**：头部的键盘按钮自定义四个快捷键——新会话（默认 Alt+N）、聚焦输入框（Alt+I）、切换计划模式（Alt+P）、停止本轮（独立页默认 Esc，仅运行中且输入框为空时生效；悬浮面板输入区单独 Esc 只收起，停止使用按钮或带修饰键的自定义快捷键）。按物理键判断（mac 上 ⌥ 改变字符也不影响）；必须带 Ctrl、Alt 或 ⌘（停止还可以只用 Esc），页面、编辑与浏览器已占用的组合（Ctrl / ⌘+K、Ctrl+R、复制粘贴撤销、新窗口 / 新标签 / 关闭标签的 Ctrl / ⌘+N、T、W 等）和另一个动作已用的组合会被拒绝。设置按用户保存在本浏览器；录入时 Tab 照常移走焦点，录入停止以外的动作时按 Esc 取消录入。非临时会话可“在新窗口打开”（地址带 `?thread=<id>`）。
- **业务上下文**：右侧“智能助手”按钮带入当前页面；列表页用 [use-agent-context.ts](../apps/web/src/views/platform/agent/chat/use-agent-context.ts) 的 `useAgentContext` 公布选中的记录，智能体就知道“这几条”指什么。新页面上下文只用于新会话，不悄悄替换已有会话的上下文；绘制流程图的页面不显示入口。

## 计划模式

会话模式为 `plan` 时，智能体只有只读工具（读取直接执行），需要你拿主意时用 `ask.user` 提问，规划好后调用内置工具 `plan.propose`（只在计划模式提供；子会话与自动化的会话不提供）提交方案：标题（≤120 字）、概述（≤2000 字）、1–30 个步骤（每步 ≤300 字）、预计改动的数据（可选，≤2000 字）、前提假设（可选，最多 10 条）。参数不合格的调用作为工具错误退回给模型。

- **方案卡**：`plan.propose` 不另设条目类型，而是一张提问条目（`question`，`questions` 为空，`proposal` 是方案），本轮像等提问一样停下（`waiting`，不占并发名额，发站内信提醒）。三个选项由本人在卡片上选，接口 `POST /api/agent/plans/:itemId`（`agentPlanDecide`：`decision` 为 `auto_review` / `ask` / `refine`，`refine` 可附 `feedback`）：
  - **批准并自动审查执行**（`auto_review`，平台此刻提供自动审查时才有，否则 400）与**批准并逐个确认**（`ask`）：`plan.propose` 这次调用记为已批准，规划的这一轮结束（同一步里别的待定卡片与调用作废），会话切到所选模式，服务器随即开新的一轮（受本人并发上限约束，满了就排在后面）。新一轮的第一条消息由运行时写成（`fromPlan` 指向方案卡，页面折叠为“按已批准的方案执行”），文字里标明“已批准的方案”并带上标题、步骤、预计改动与假设，模型据此执行、用 `plan.update` 报告进度。
  - **继续完善**（`refine`）：模式不变，意见作为下一条用户消息并入本轮，本轮接着规划，模型通常再提交一张新的方案卡。
  - 卡片记下选择（`choice`：`decision`、`decidedBy`、`decidedAt`、`feedback`），之后只读显示。卡片等待时直接在输入框发消息，等于带这条消息“继续完善”；点“停止”时卡片作废（`expired`）。已决定或已作废的再决定 409；`POST /api/agent/questions/:itemId` 不能回答方案卡（400）。
- **只有本人能离开计划模式**：方案卡上的批准，或输入框的模式选择器；模型没有任何工具或文字能切换模式。别人的会话与别的租户的方案卡 404。
- 页面：方案卡列出标题、概述、编号步骤、将改动的数据与前提假设；平台提供自动审查时“批准并自动审查执行”是主按钮，否则“批准并逐个确认”是主按钮；卡片本身获得焦点时 Enter 等于主按钮；“继续完善”先展开意见框（可不填，Enter 提交、Shift+Enter 换行、Esc 返回）。

## 子智能体

内置工具 `agent.delegate` 把 1–3 个互相独立的子任务交给子智能体并行执行（[subagents.ts](../apps/server/src/core/agent/runtime/subagents.ts)）：

- 每个子任务开一个子会话（记 `parent_thread_id`），以父会话发起人的身份、权限、数据权限与租户运行，不用记忆（不读也不参与记忆提炼）。子会话不进会话列表、搜索与分享（分享 409），不能再发消息，也不能分叉（都回 409），只有本人能打开（别人与别的租户 404）；父会话里的“子任务”卡片列出每个任务的状态与摘要，按真实状态汇总进行中、完成与异常，点选任务即可在主对话旁查看只读过程，返回时保留主任务位置；分享快照不额外请求私有子会话。删除父会话或撤回分派的那一轮时，子会话一起删除。
- 子智能体只有父会话此刻可用工具里的只读部分，而且只留策略为“自动执行”的（会停下等审批的只读工具不给）；不能再分派、不能反问用户，也不写图表、报告与图片（产出由父会话来写）；子会话总是只读（本人事后改了它的模式也一样）。每轮最多 8 步（平台步数上限更小时取平台的）。要改数据时，子智能体只能把建议写进摘要，由父会话里的写入工具走正常审批。
- 子会话能读的链接只有分派时父轮可读的那一份，加上它自己搜索带回的；任务文字是父模型写的，其中的链接不算，所以网页诱导父模型写进任务里的地址不会被读取（防外泄）。
- 子轮次在父轮的这次调用里直接推进，不排队；并发名额由父轮占着，子轮次不另算，所以一个父轮最多再带 3 路同时进行的模型调用。受暂停与每日额度约束，用量记到发起人名下并计入父轮；子轮的积分消耗同时计入父轮预算，下一次调用前检查已发生消费；在途并行调用可能越过预算。父轮被停止、暂停或超时时，子任务一起停，卡片显示“已停止”；外部服务器在子会话里弹出表单时（没人回答）那个子任务作废。
- 子智能体读过网页，它们的摘要作为不可信内容交回父模型（模型被告知只当数据看）；它们读过与搜到的链接计入父轮的可读链接，父轮可以接着读取、在报告里引用。
- 这次调用被重做（重启、丢锁）时按调用 id 找回已建的子会话，已结束的直接取结果，不会重复建会话、重复花钱。

## 深度研究

平台技能 `deep-research`（深度研究；种子 [research-skill.seed.ts](../apps/server/src/db/seeds/agent/research-skill.seed.ts)，正文是英文，模型按用户的语言作答；描述是种子键 `seed.agentSkill.deepResearch`，各语言的文字在 `packages/shared/src/i18n/<语言>/seed.json`；管理员可在技能页修改或停用）。在输入框里用 `$deep-research` 开始的一轮是**研究模式**：步数与时长上限改用 `agent.limit.research_steps` / `agent.limit.research_seconds`（root 专用参数）。只认平台的那一份技能：本人或租户建的同名技能（取用时优先）不会得到研究模式的上限。

技能正文要求先用 `plan.update` 列计划，再多来源检索与阅读（可用 `agent.delegate` 把子问题分给子智能体），有数字时用 `chart.render` 画图表，最后调用内置工具 `report.write` 写一个报告条目：标题、Markdown 正文、按 `[1]`、`[2]` 编号的引用列表。引用只认本轮可读的链接（用户给的、搜索带回的，与 `web.fetch` 同一份）；别的链接保留位置但去掉地址，页面标为“未核实”，模型也会被告知。报告可导出 Markdown、打印为 PDF（打印时只打印这份报告），正文里的每张表格都可单独导出 xlsx。

## 图表、图片与导出

- `chart.render`（只读）：声明式图表配置（`agentChartSpec`：柱、线、饼、表格；最多 12 个系列、每个 200 个值，只有数字、短文字与空值），写一个图表条目。柱、线、饼图的每个系列逐个对着类别，饼图只有一个系列；表格类的类别是表头、每个系列一行。页面用现有的 `QwChart`（ECharts）渲染，表格直接渲染成表格，不执行任何代码、不拼 HTML。
- `image.generate`（只读）：只在某个启用的提供方模型标了“图片”时提供。走兼容 OpenAI 的 Images 接口（提供方的同一个客户端，只收 base64 结果，不另行下载链接），图片经端口 `AGENT_IMAGE_STORE` 由存储模块存成发起人名下的私有文件（业务标签 `agent.image`），写一个图片条目（文件 id 与说明）。生成前看暂停、本轮与每日额度，用量只按提供方实际报告记账。无法按 Token 计价时仅使用管理员明确设置的单张图片后备积分；未配置后备费率则记为无法计价，不伪造固定 Token。失败请求不使用单张后备费用。图片解码后约 20 MB 为上限，返回的 base64 超出时不解码直接失败；每轮最多生成 4 张图片；存储前按内容识别类型，不是 png / jpeg / webp / gif 的（例如 HTML、SVG）422、不建文件；条目里的宽高从文件头读出，读不出就不填。按调用幂等：重做时按调用键找回已存的图片，不再生成。尺寸可选 `1024x1024`、`1536x1024`、`1024x1536`，模型不支持的尺寸由提供方报错。删除会话时一并删除它生成的图片文件，撤回一轮时删除这一轮生成的。
- 导出：`GET /api/agent/items/:itemId/xlsx` 把图表的数据或报告里第 `table` 张表格（从 0 起）导出 xlsx，只给条目所在会话的本人（子会话里的条目也属于父会话的本人），别人与别的租户 404。单元格写成纯值：数字照写，以 `=`、`+`、`-`、`@` 等开头的文字前加单引号，从不成为公式。

## 自动化

菜单“智能体 → 自动化”（权限点 `agent.automation.use`）：让智能体在后台按时、在某个业务操作之后或手动运行一个技能或一段提示词。每次运行开一个隐藏会话（不进会话列表，在运行历史里点“打开会话”查看全过程；里面只能确认或拒绝审批、回答提问，不能再发消息、分享或分叉，都回 409），以创建人的身份、权限、数据权限与租户执行，每一轮开始时还要核对创建人仍有 `agent.automation.use`（共享的另需 `agent.automation.share`）；暂停、每日积分预算、并发上限与用量记账照常适用。隐藏会话里本系统工具（`@McpTool`）的结果也按不可信内容交给模型（模型被告知只当数据看，不照着其中的文字办事），因为业务数据里的文字可能是别人写的。同一条自动化上一次运行还没结束时，新的触发不运行，记一条“已跳过”（原因 `overlap`），立即运行回 409。自动化会话里列出的技能与 `skill.load` 只有创建人本人的个人技能与平台技能（不含全租户技能，同名的全租户技能也不会顶替平台的那一份）。运行结束时把回答摘要写进运行记录，并按自动化的通知方式发站内信（模板 `agent.automation.result`），自动化或个人通知设置里“自动化结果”开了邮件时再发邮件。

- **定时**：5 段 cron（分 时 日 月 周）加 IANA 时区，最短 5 分钟一次（保存时按接下来一年内的触发时刻检查），页面给常用预设。用队列的重复任务实现（每条自动化一个，存在 Redis 里，多实例下每次只触发一次；同一条自动化的同一个计划时刻只运行一次，任务被队列重复交出也不会多开）；停用、删除或改 cron 时同步更新或移除，服务启动时按库里的自动化重新登记。
- **业务事件**：监听某个 `@ActionLog` 动作（如 `demo.customer · 新增`），可选的事件只列你有该资源浏览权限（`<domain>.browse`）的。事件带记录 id：创建人须有浏览权限；记录登记了批量目标时，还要以创建人的数据权限能读到这条记录，读不到（不在数据范围内、已删除）的事件不运行、也不留记录。没有登记批量目标的资源无法逐条核对数据范围：它若受数据权限约束，只有能看全部数据的人能监听它的事件；不受数据权限约束的资源只看 `<domain>.browse`。要让其他人也能监听，给该资源登记批量目标（见下文“批量目标”）。同一事件只触发一次；一条自动化一分钟内只因事件运行一次（其余丢弃），再受每日次数限制。智能体自己代为执行的写入、智能体与 MCP 自身的操作不算业务事件。
- **手动**：“立即运行”（创建人才有；停用的自动化也能手动运行）。
- **停用与删除**：停掉还没结束的运行（中断进行中的一轮，作废还在排队的消息），运行记为取消；删除自动化时一并删除它的隐藏会话。停用那一刻正在执行的那一次工具调用会执行完（与对话页的“停止”相同），之后不再放行任何写入。
- **配置方案**：可选一个创建人能用的[配置方案](#配置方案)（别人的个人方案 400）。每次运行按创建人此刻的身份重新取：带入方案的模型与推理强度（模型已停用时用平台默认，推理强度只给支持它的模型），工具清单与额外说明在运行时生效；会话模式不取方案的，由写入模式决定。运行前方案被删除或已不能用时照常运行、不用方案，运行记录注明“配置方案已不可用”。
- **写入模式**：`只读`（默认，不提供写入工具）；`询问`（写入停下，确认请求经站内信发给你，在隐藏会话里确认后继续）；`预先同意`（建或改自动化时逐个勾选允许的本系统写入工具；加入新工具须输入当前密码，与锁屏同一套试错计数，撤掉不用密码）。预先同意只在这条自动化这次运行开的那一轮里、由创建人本人运行、工具在清单里且此刻仍有效时放行（审批卡片记为“预先同意”），清单外的写入照常停下等人。预先同意的自动化只能用创建人本人的个人技能、本人的个人配置方案或平台技能，否则保存回 400（提示“预先同意写入时只能用本人的技能和配置方案，或平台技能”）。技能按保存时的那一个（按 id 与范围，不按名字）绑定，之后别人建的同名技能不会顶替它。技能正文或方案的额外说明一改，这些同意就失效，须重新勾选并输入密码；保存时换了技能或方案，也算新的同意，要输入密码。绑定的技能被删除或停用、方案被删除或改成全租户共用（别人能改它的说明）后，运行时不再使用它们（方案的运行记录注明“配置方案已不可用”），预先同意随之失效，写入交给人确认。每个条目同意时记下凭据：与这个工具有关的生效事实的摘要（创建人是否持有工具所需的权限点、给出它的角色编码与数据范围含自选部门、本人的部门与部门路径、工具所需的套餐功能）与工具平台开关行的值（启用与策略，没有行时记为“无”）。每次决定时重算比对，不一致（创建人在这个工具上的权限或数据范围变了，管理员动过这个工具的开关或策略）、创建人失去自动化权限、工具被停用或策略为 `deny` 时这项同意作废（只有事实恢复到与同意时完全相同才算仍有效；动过开关或策略的不会恢复）：卡片写明“预先同意已失效，需要重新同意”，自动化列表里该工具标为“已失效”，须重新勾选并输入密码。别的租户续期、改无关的菜单、改界面语言不影响它。外部 MCP 工具与内置工具不能预先同意。`自动审查`（只在平台配置了审查模型时可选，没配置时保存回 400）：策略为 `ask` 的写入交给审查模型决定，驳回、拿不准与其他写入停下等你确认（同对话页的自动审查模式）；运行时审查模型已不可用的，这次运行记为“已跳过”。
- **共享**：有 `agent.automation.share` 的人可以建全租户共享的自动化，本租户有 `agent.automation.use` 的人都能看到，只有创建人能改、启停、运行与看历史。它以创建人的身份运行；创建人被停用、删除或失去对话、自动化或共享权限后不再运行：运行前检查，第一次发现时记一条“已跳过”并写明原因，同时停用这条自动化、站内信告诉创建人（模板 `agent.automation.stopped`），之后不再触发。
- **上限**（root 参数）：`agent.limit.automations_per_user`（默认 `20`，每人最多几条）与 `agent.limit.automation_runs_per_day`（默认 `50`，每条每天最多运行几次，UTC 日，按 Redis 原子计数，跳过的不算）。超出时新建与手动运行回 429，定时触发记一条“已跳过”。暂停时手动运行回 503，定时与事件触发记“已跳过”。

接口见 [agent.schema.ts](../packages/shared/src/platform/agent/agent.schema.ts) 的 automations 部分；实现在 [core/agent/automation](../apps/server/src/core/agent/automation/)，预先同意的审批审查者在 [pre-approval.ts](../apps/server/src/core/agent/automation/pre-approval.ts)，页面在 [automation/index.vue](../apps/web/src/views/platform/agent/automation/index.vue)。

## 安全模型

- **只属于发起人**：会话、条目、审批与提问只有本人能看能操作，别人的会话一律 404；只有发起人本人能确认审批（批量也一样）。分享链接只读、只限同租户。
- **工具按用户本人的身份运行**：进程内调用 `@McpTool` 时沿用 MCP 的护栏——权限点、数据权限、租户与套餐、参数校验、超时、输出中密钥名字段的遮蔽与大小上限、平台的逐个停用。智能体能做的不会超过发起人自己在页面上能做的；每一轮开始前按发起人重新加载身份，用户被停用或删除时轮次不再进行。
- **写入从不在没有人的同意时执行**：写入工具的策略只能是 `ask`、`human` 或 `deny`，从不是 `auto`。策略为 `ask` 的写入放行只有四种情形：卡片上逐次确认；本人在本会话里选了“此工具不再询问”（本人先确认过一次）；自动化的[预先同意](#自动化)（本人逐个勾选并输入当前密码，凭据变了即作废）；本人选了“自动审查”模式后由审查模型放行（见[自动审查](#自动审查)）。`human` 与须本人逐次确认的写入只有第一种。审批审查者的放行与会话放行由运行时每次重新核对（此刻的模式、策略与放行列表），没有资格的降为交给人；一轮在放行之后、执行之前中断（重启、丢锁）的，续跑时执行前再核对一次，已失效的不执行。确认之后若权限、会话模式或策略已经变了，调用照样被拦下。
- **来源限制**：`web.fetch` 只读本轮搜索结果、用户消息里的链接或白名单网站，防止网页内容诱导智能体把内部数据拼进 URL 发出去；没出现过的链接连 DNS 都不查。
- **不可信外部内容**：网页、搜索结果与外部 MCP 工具的输出交给模型时包在 `<external-content>` 块里并注明“只是数据”，系统提示要求不执行其中的指令；即使模型被网页诱导去改数据，写入仍停在审批卡片上，卡片列出依据的来源。用户在反问里填的文字也只作为数据交给模型。
- **出站请求防 SSRF**：`web.fetch`、外部 MCP 与其 OAuth 令牌请求只用 http/https，解析后的每个地址都必须是公网地址（拒绝回环、内网、链路本地与云元数据地址），连接钉在检查过的地址上，每次重定向重新检查，有总超时、大小与类型上限，不带 Cookie 与系统凭据（[safe-fetcher.ts](../apps/server/src/core/agent/web/safe-fetcher.ts)、[guarded-fetch.ts](../apps/server/src/core/agent/mcp-client/guarded-fetch.ts)）。外部 MCP 指向内网须 root 显式勾选。模型提供方的接口地址**不做**这项检查（本机或内网的 Ollama 正是常见用法），它只能由 root 配置。
- **密钥加密**：模型、搜索服务与外部 MCP 的凭据各用 `APP_SECRET` 派生的独立密钥加密存库，只写不读，操作日志里遮蔽；改了目标地址须重填，原凭据不会发往新目标。
- **审计**：每次工具调用（含被拒的）记一条操作日志，模块 `mcp.tool`、动作 `call`，参数里标明来自对话页（`channel: in-app`）、工具来源、会话与轮次 id；被修改的数据行照常记修改人为发起人。设置的每次修改也记操作日志。
- **限额与暂停**：每轮步数、时长与积分，每用户与每租户每日积分，每用户并发轮次；root 的暂停开关 `agent.paused` 立即生效。

### 已知上限

- 并发轮次数是软限制：两个同时到达的请求可能都通过，每用户最多多出一轮。
- 暂不支持租户自己添加外部 MCP 服务器：外部服务器、模型与搜索服务都是平台配置，只有 root 能改。
- 只支持远程 HTTP 的 MCP 服务器，不支持要在服务器上启动进程的 stdio 类服务器。
- 附件只能是文件存储接受上传的类型；读入模型的只有上文列出的文本、表格与图片类型。
- 撤回一轮不回滚它已经执行的写入；工具超时只结束等待，已经开始的数据库操作无法中断（同 MCP）。
- 模型的回答与判断可能出错：审批卡片上的旧值 → 新值与来源请逐条核对。

## 给自己的模块加工具、批量目标与技能

分步配方见 [给智能助手加工具与技能](ai/recipes/agent-skill.md)；只给智能体用的内置工具、上下文与审批规则见下一节[扩展点](#扩展点)。要点：

### 工具

工具与 MCP 工具是同一个东西：一个 provider 方法加 `@McpTool`（[mcp-tool.ts](../apps/server/src/core/mcp/mcp-tool.ts)，写法与声明规则见 [MCP 文档](mcp.md#给自己的模块加工具)）。智能体额外用到的是写入工具的 `preview`：同一个 provider 上一个方法的名字，收到同样（已校验）的参数，返回 `{ target, fields: [{ field, from, to }] }`，审批卡片据此显示“改哪条记录、每个字段的旧值 → 新值”。预览方法同样在调用者的数据权限下读数据，读不到就抛 404。

```ts
@McpTool({
  name: 'crm.customer.update',
  title: 'Update a customer',
  description: 'Sets the level or the note of a customer. Cite your sources.',
  perm: customerPerms.modify,
  kind: 'write',
  input: updateInput,
  output: updateOutput,
  preview: 'previewUpdate',
})
async update(dto: z.output<typeof updateInput>) {
  // 写入前在事务里 lockScopedIds，再比较与写入
}

/** 审批卡片：会改哪个客户、每个字段的旧值 → 新值。 */
async previewUpdate(dto: z.output<typeof updateInput>) {
  const c = await this.customers.get(dto.id)
  return { target: `${c.name} (#${dto.id})`, fields: [{ field: 'level', from: c.level, to: dto.level }] }
}
```

### 批量目标

想让列表页对选中行批量执行技能，在同一个 provider 上加 `@AgentBatchTarget({ target, perm, tools })`（[batch-targets.ts](../apps/server/src/core/agent/batch/batch-targets.ts)），并实现 `AgentBatchTargetProvider.batchLabels(ids)`：返回调用者能读到的 id → 记录名（用 `scopedQb`，读不到的不放进结果）。`target` 写 `<domain>.<resource>`，`perm` 是列表的 browse 权限点，`tools` 是批次页“全部确认”可以一起确认的写入工具（必须带 `preview`，预览目标是这一行的记录；不在清单里的写入一律逐条确认，防止某条记录里的网页内容诱导出对别的记录或别的系统的写入被一并放行）。智能体关着时没有人扫描它，模块照常工作。列表页用 `agentBatchApi.create({ skill, target, ids })`（[agent-batch.ts](../apps/web/src/api/platform/agent-batch.ts)）建批次，再打开路由 `agent-batch`，写法同示例客户的列表页。

### 技能

项目自带的技能写成种子：在项目种子里像 [customer-sample.seed.ts](../apps/server/src/db/seeds/demo/customer-sample.seed.ts) 那样只在第一次写入 `agent_platform_skill`（管理员之后的修改与停用保留），登记到 `apps/server/src/db/seeds/index.ts` 的 `SEEDS.project`。技能正文里写清楚每一步用哪个工具、只改什么、查不到时怎么办，并在 `tools` 里只列需要的工具。也可以不写代码，直接在“技能管理”页新建或导入 `SKILL.md`。

## 扩展点

运行时留了三个扩展点，模块把自己的 provider 放进 `providers` 就能挂上去，不必改智能体模块，也不改运行时主循环。启动时 [agent-extensions.ts](../apps/server/src/core/agent/runtime/agent-extensions.ts) 扫描所有 provider 登记它们；智能体关着（`APP_AGENT=false`）时没人扫描，模块照常工作。声明与接口都在 [agent-ports.ts](../apps/server/src/core/agent/agent-ports.ts)，模板自己的用法：记忆与配置方案说明 [memory-tools.ts](../apps/server/src/core/agent/memory/memory-tools.ts)，自动审查 [auto-reviewer.ts](../apps/server/src/core/agent/runtime/auto-reviewer.ts)，预先同意 [pre-approval.ts](../apps/server/src/core/agent/automation/pre-approval.ts)。分步配方见 [给智能助手加内置工具、上下文与审批规则](ai/recipes/agent-extension.md)。

| 扩展点                                  | 什么时候用                                                                                                           | 不该用它做的                                                                                 |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 内置工具 `@AgentBuiltinTool`            | 只在对话里有意义的能力：要用本轮上下文（会话、轮次、界面条目、`ask`、本轮可读链接），如 `plan.update`、`memory.save` | 读写业务数据：用 `@McpTool`（权限点、数据权限、超时与审计由同一套护栏负责，见[工具](#工具)） |
| 上下文贡献者 `@AgentContextContributor` | 每轮给模型补一段与本人相关的背景，如“关于你的记忆”、配置方案的额外说明                                               | 规则与约束：它只是用户角色的上下文，从不进系统提示，模型可以不照做                           |
| 审批审查者 `@AgentApprovalReviewer`     | 写入停下等人之前按业务规则先判断：驳回明显不对的、把有风险的交给人（如金额过大）                                     | 绕过人的同意：运行时只承认有资格的放行（见下）                                               |

约束：

- **内置工具**：内置工具之间名字不能重复（重名启动失败）；与本系统工具（`@McpTool`）同名时内置工具优先、那个本系统工具在对话里被遮住，所以内置工具请用不会与 `@McpTool` 冲突的名字（例如不带 `<domain>.<resource>` 前缀的动词名，或单独的前缀）。参数是 zod 对象 schema，执行前校验。`kind: 'write'` 与其他写入工具走同一条审批路径——停下等人或经审批审查者，只读与计划模式下不提供，`$技能` 或配置方案给了工具清单而清单里没有它时也不提供；`humanOnly: true` 的只能由人逐次确认（不能本会话放行；管理员设的策略除 `deny` 外都按 `human`，从不交给审批审查者）。`kind: 'read'` 不经审批，重启或丢锁后可能再执行一次，所以**必须按调用幂等**：不开会话、不调用模型、不做无法重复的写入；写界面条目用 `ctx.items.add`（同一次调用里重做时替换上次那一条）。两类都受“工具策略”页的平台开关与策略约束。内置工具不经 MCP 的护栏，按 `ctx.principal` 的身份办事，权限点与数据检查自己负责；外部来的文字放进结果时标 `untrusted: true`。
- **上下文贡献者**：每次请求模型前按 `order`（小的在前，缺省 100）调用，返回的文字以**用户角色**的消息放在历史最前面（超过 20000 字符截断），计入 `/status` 的上下文估算；失败只记日志、跳过这一段。`turnId` 为 `null` 时是 `/status` 的估算，**不得有任何副作用**（不写库、不调用模型、不记用量），只读出会给的文字。临时会话、关了记忆等会话设置在 `ctx.thread` 里，由贡献者自己判断。
- **审批审查者**：写入停下等人之前按 `order` 调用，**第一个非 `null` 的结论生效**（`escalate` 也结束链条，后面的审查者不能再放行），全是 `null` 时照常出审批卡。策略不是 `ask` 的工具（`deny`、`human`）、本会话已放行的工具、只读与计划模式、暂停时从不调用。审查者**须响应 `ctx.signal`**：中断时运行时不再等它；自己调用模型时使用 `ctx.invokeModel()`，由运行时检查预算并持久登记、观察和结算调用。审查者只看到工具、参数、改动预览与来源，看不到任何工具的输出。**运行时只承认有资格的放行**：`by: 'review'` 要求工具此刻的策略是 `ask`、会话此刻是“自动审查”模式；`by: 'pre_approved'` 只在自动化开的会话里、由预先同意本身复核通过才算；其余的 `approve` 一律降为交给人。驳回与交给人都停下等人，理由显示在卡片上；人也拒绝时驳回理由按不可信数据交给模型。
