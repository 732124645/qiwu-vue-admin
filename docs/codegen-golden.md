## Windows (PowerShell 5.1)

Native Windows 11 + Windows PowerShell 5.1 (including the cmd entry) is verified for development and the full local gate (`pnpm ci:local --serial`); symlink-protection tests skip without file-symlink privilege; server deployment and App / mini-program publishing on Windows are not verified. Hand-typed `pnpm.cmd` commands avoid the `.ps1` shim without changing execution policy. The `.cmd` exists only with npm / Corepack installs; with standalone `pnpm.exe` (winget / get.pnpm.io), use plain `pnpm`.

After a deliberate template/config change, check the isolated test database (`qiwu_test` / Redis 15), `.env.test` and the optional local override `.env.test.local`; credentials belong in `.env.local`. Each command below resets that isolated test database. Adopt output only in a clean target set, review `git diff`, then recheck; stop on any failure:

```powershell
pnpm.cmd gen:check-golden --write
if ($LASTEXITCODE -ne 0) { throw "Golden update failed; inspect touched paths" }
git diff
if ($LASTEXITCODE -ne 0) { throw "Diff failed" }
pnpm.cmd gen:check-golden
if ($LASTEXITCODE -ne 0) { throw "Golden check failed" }
```

Use `pnpm.cmd gen:check-golden` alone for the default read-only comparison of generated files (the test database is still reset). Node writes UTF-8 bytes directly; do not pass diff output through PowerShell 5.1 pipes or redirection. The normal write guards and partial-failure recovery instructions below apply on Windows too. File-symlink protection tests may skip when the current account lacks the required privilege.

## Conventions the templates must reproduce

- **Names** (table `iam_position`): domain `iam`, business `position`, class `Position` (+`Service`/`Controller`/`Module`), URL `/api/iam/positions`, perms / `@ActionLog` domain / field-label domain / `table-id` `iam.position`, menu `route_name` `iam-position`, `route_path` `/iam/positions`, `component` `platform/iam/position/index`, `component_name` = `defineOptions` name `IamPosition` (form `IamPositionForm`), web export `positionApi`, spec `iam-position.e2e-spec.ts`. A class or field name never takes one the rendered code uses already (`CG_RESERVED` in `@qiwu/shared`: the templates' imports and constants, globals like `Date`, JS reserved words, the service's locals): import derives another default (`cfg_param` → `SettingsParam`, a field `…Value`, field names unique within the table), save and render refuse one (422 C3002). The parent menu is required and must be a group menu's route name (422 C3008).
- **Schemas**: every input schema `.register(fieldDomains, { domain })`; columns with a DB default are `.optional()` (no zod `.default()`, so a partial PUT never resets them), nullable columns `.nullish()` (the edit form sends back the `null` it loaded); query = `pageQuery([...sortable]).extend({ filters })`, varchar filters `trim().max(n)`, booleans `z.stringbool()`; a column's configured example (`cg_column.example`, typed like the column: number, boolean, else a string literal, a decimal text with its scale's digits) is its body field's Swagger example, `.meta({ example })` before `.optional()` / `.nullish()` (zod writes it as the OpenAPI 3.0 `example`; the generated spec takes it as test data and checks it in `/api/docs-json`), columns without one render as before; generic bodies `idsBody` / `enabledBody` / `pageVo` come from `@qiwu/shared` (`common/crud.ts`).
- **Service**: list filters only in `filter()` (shared by `page` and `exportRows`, which yields the export in batches of `EXPORT_BATCH` = 1000 rows: offset pages of the same scoped, filtered, sorted query; generated services never override it): `*name`/code-like varchar → `LIKE :x` with `contains()` (wildcards literal), enums/booleans → `=`; a name column that seeds fill with `seed.<biz>.*` keys also matches the text users see: `seeded = seedKeysLike('seed.<biz>.', name)` (`core/i18n/seed-names.ts`, texts from the shared `packages/shared/src/i18n/<lang>/seed.json`), then `andWhere(seeded.length ? '(t.name LIKE :name OR t.name IN (:...seeded))' : 't.name LIKE :name', { name: contains(name), seeded })`; `options()` = enabled rows `{ id, name }` by `sort_no, id` through `scopedQb`.
- **Constraints and config, not code** (every table soft-deletes, no foreign keys): uniqueness = unique index `(…, alive)` (errno 1062 → 409 `duplicate`; a deleted row's value is free again), "in use" = the config's `options.referencedBy` (`[{ table, column, label }]`): the entity file calls `referencedBy('<table>', { table, column })` (core/db/references.ts) under a `// <label>` line, and the base `remove` (`softDeleteRows`) answers 409 `in_use` while a live row of `table` holds one of the ids in `column`; a master-sub master registers its sub tables by their fk as `cascade: true` (the rows are soft-deleted with it). The writing side is the base's too: create/update of a row holding a registered reference to a missing or deleted row → 404 (`assertReferencesLive`); a master-sub `save<Sub>` (sub rows bypass the base) calls it itself before each insert (the row with its fk) and update (the sent row against the stored one: an unchanged value is not judged or locked again). No `assertUnique` / reference checks written by hand in generated services.
- **Routes** (static before `:id`, `ParseIntPipe`): `GET /` browse · `GET /export` export (the list query without paging → a non-`async` handler returning `this.excel.export(<plural>, <biz>Columns, this.<biz>s.exportRows(query))`: the batches go to `ExcelService.export` un-awaited, it reads the first one before the response starts and streams the rest; `@ActionLog` verb `export`, `@ApiProduces(XLSX_TYPE)`) · `GET /options` any signed-in user · `GET /:id` view · `POST /` create + `@Idempotent()` + `@ActionLog(bizId from the result)` · `PUT /:id` and `PUT /:id/enabled` modify · `DELETE /:id` and `POST /batch-delete` (`@HttpCode(200)`) remove. Every non-GET: `@ActionLog({ domain, verb })` with verb = perm verb. Swagger: `@ApiTags(domain)`, `@ApiOperation({ summary })`, `@ApiEnvelope(vo | pageVo(vo) | none, 201 for POST)`; query/body docs come from the zod schemas.
- **Seed**: the parent group looked up by `route_name` among `kind=group` rows (deleted → the module's menus skipped with a notice; missing → an error, for a project group pointing at `db/seeds/project/menu-groups.seed.ts`); a platform / workflow page upserts its `parent_id`, `icon` and `sort_no` each run, a project page (group `biz`, the demo samples too) writes them only on insert (moved in 菜单管理, it stays); page `name` `menu.<domain>.<biz>`, `keep_alive` 1, `lucide:*` icon (Lucide names), `sort_no` step 10; actions `browse/view/create/modify/remove/export` (`import` where the module imports) named `menu.action.<verb>`; no demo rows.
- **Excel columns**: `<biz>Columns: ExcelColumn[]` next to the service (`core/excel`), the list's columns in list order: `label` = the field label key, `seedName: true` on a seeded name column, `type: 'number' | 'boolean' | 'datetime'`, `dict` for dict/boolean columns (`core.enabled`), audit times `only: 'export'`, the free-text column `width: 40`.
- **List page** (layout): root `div.qw-page` without a page header (the active tag and breadcrumb name the page), `el-card.qw-search-panel` (inline search form; last item `el-form-item.qw-search-actions`: `type="primary" plain` search with a `lucide:search` icon + default (outlined) reset — the create button stays the page's one solid primary), `el-card.qw-table-panel` (`TableToolbar` with a `lucide:plus` create button, `QwTable`, `Pagination`); `useCrudList({ api, filters, sort })` (`sort: 'sortNo'` when the table has `sort_no`, else `'-createdAt'`; `QwTable :filtered="filtered" @reset-filters="reset"` for the "no match" empty state); search form with `name`d inputs, `DictSelect` for dict/boolean columns; `v-perm` on create / export / batch delete / delete (export = a default button with a `lucide:download` icon after create, `:loading="exporting"`, `exportXlsx(`${t('menu.<domain>.<biz>')}.xlsx`)` from `useCrudList`), batch delete also `v-if="selection.length"`; the row's edit button only with both `modify` and `view` (`canEdit = computed(() => perm.all([perms.modify, perms.view]))` over `perm = usePerm()`, `v-if="canEdit"`: the form loads `GET /:id`; computed, so the flags follow a permission reload); the table is `QwTable` over a module-level `columns: QwColumn[]` (`{ prop, label: 'field.<domain>.<biz>.<prop>', sortable: true (server sort), width | minWidth, align, showOverflowTooltip }`, labels are keys; short columns a fixed `width` by kind (code 140, name 160, numbers 120 `align: 'right'`, enabled 100, dates 160; another text of at most 32 characters as wide as its longest value, ≈ 7px a character), never narrower than the longest locale's header plus the sort caret (`qwColumn` in `codegen/crud.ts` estimates it), the one free-text column (`note`) last with `minWidth` so it takes the spare width), `table-id="<domain>.<biz>"` on both `QwTable` and `TableToolbar :columns` (user column settings via `useTablePrefs`, stored as `table.<domain>.<biz>`), `selection`, custom cells only as `#cell-<prop>="{ row }"` slots, row buttons in `#actions`; `enabled` = `el-switch size="small"` when the user has `modify`, else `DictTag code="core.enabled"`; seeded names through `tx()`; dates `dayjs(...).format('YYYY-MM-DD HH:mm')`.
- **Form**: a dialog content component: `defineProps<{ id?: number }>()`, `defineEmits<{ done: [saved: { id: number }]; cancel: [] }>()`, `useCrudForm({ api, schema: <biz>Create, emptyModel, id, emit })`; `el-form label-position="left"` (no `label-width`: in a dialog the labels share one grid column as wide as the longest, 96px at least, styles/element.css) then a `div.qw-dialog-footer` with cancel (`emit('cancel')`) and save (`:loading="submitting"` → `submit`); labels `field.<domain>.<biz>.<prop>`; seeded names need nothing in the form: `useCrudForm` shows a loaded `seed.*` key as its text and saves the key again while the text is unchanged. The list page opens it: `openForm(id?)` = `await openDialog(<Biz>Form, { id }, { title: () => t(id ? 'crud.title.edit' : 'crud.title.create', { name: t('<domain>.<biz>.entity') }) })`, then `refresh()` when it resolves with a result. Editing loads `GET /:id`, so edit needs the `view` perm too (the list hides the edit button without it). `form_cols` 2 / 3 (position and the other G0 samples keep 1, which renders none of this): `class="qw-form-cols-<n>"` on the `el-form` lays the fields out as that many label + field pairs a row (styles/element.css), free text and uploads get `class="qw-form-wide"` (a whole row), and the list opens the dialog 880px / 1200px wide.

The spec's test data: a text or dict column shorter than a tag takes the tag's end, a dict column without an example an enabled entry of its dict that fits the column (read in `beforeAll`); the shared `logOf` (`test/setup/audit.ts`, polls up to 5 s for the fire-and-forget action log row) is imported and helpers such as `dictLabel` are emitted only when a case uses them.
- **Secret widget**: nullable `*_enc` `varchar`/`char` columns default to `secret`. The entity keeps the `*Enc` property with `select: false`; the create/update body and password form use its name without `Enc` as a write-only field. A nonempty value is boxed with `SecretBox`, while an empty update keeps the stored box. The generated VO, list, detail, filters, options and Excel omit the column. The plaintext cap accounts for the box's base64url expansion; master-sub secrets are refused.
- **Strings**: labels only from shared `field.*`, actions/messages from `crud.*`, nothing hard-coded; both languages always. A module's own keys live only in its fragments, never in an existing locale file: web `apps/web/src/locales/<lang>/<domain>.<biz>.json` (`<domain>.<biz>.entity`, `menu.<domain>.<biz>`) and shared `packages/shared/src/i18n/<lang>/modules/<domain>.<biz>.json` (`field.<domain>.<biz>.*`). A fragment holds whole top-level namespaces and every loader deep-merges it (`mergeLocaleFile` in `@qiwu/shared`: web vue-i18n `core/i18n` and `sharedMessages` in `core/form/zod-rules.ts`, the server's nestjs-i18n loader from `src/i18n` + shared or the built `dist/i18n`, Playwright `msg()`); `i18n:check` pairs each fragment with its other-language file (same keys) and rejects a key that two files define, web or server against shared too. Keys shared by all modules (`menu.action.*`, `crud.*`, `field.common.*`) stay in their namespace files.

## Design conventions

1. Seed file location: the menu seed stays beside the module as `<biz>.seed.ts` (the module layout shown here), not `db/seeds/<domain>/<biz>.menu.ts`; the generator prints the registration lines (module import, `SEEDS` entry, shared export, the parent chain's `menu-groups.seed.ts` lines for a project module) and never edits existing files.
2. Locale fragments: per-module fragments with loader and `i18n:check` support (see **Strings**); position's own keys moved into `iam.position.json` (web) and `modules/iam.position.json` (shared), so the module re-renders without touching a shared locale file.
3. Tests: the generated `<domain>-<biz>.e2e-spec.ts` holds only the standard cases; module-specific cases of a G0 module go into a hand-written sibling `<domain>-<biz>-extra.e2e-spec.ts` (here `iam-position-extra.e2e-spec.ts`). G0 files are never hand-edited after the round-trip.
4. `created_at` range: the rules table puts it into the list query as `createdAtFrom` / `createdAtTo` (demo_book has it); position's config switches it off (`in_query` 0), so position keeps no range filter.
5. Config of the golden modules: the import defaults plus the edits in the seeds `apps/server/src/db/seeds/codegen/iam_position.cg.ts` and `demo_book.cg.ts` (labels, seeded name, menu icon/sort, options; `pnpm db:seed` stores it in `cg_table` / `cg_column`, domain `codegen`). `pnpm gen:check-golden` (`scripts/gen-check-golden.mjs`, a `pnpm ci:local` step) resets the isolated test DB/Redis pair (`.env.local` → `.env.test`; normally `qiwu_test` / Redis 15), renders every table that has a `db/seeds/codegen/<table>.cg.ts` with the compiled CLI and diffs each file against the repository; `codegen-render` renders position from the same seed and compares byte for byte too. Change a template, the module or its `.cg.ts` only together. Position's server, shared, seed, spec and web files are re-rendered together: `@generated` header, DB column comments as JSDoc on the entity, generic doc comments and Swagger summaries, a spec driven by `body(tag)` test data and the app's own translations (behaviour unchanged).
6. demo_book (G0, the generator's own sample): `demo_book.cg.ts` switches on the detail drawer, export and import, so the optional template paths are rendered, compiled and tested too; its nullable `dept_id` (a dept holding books is in use: `referencedBy('iam_dept', …)` hand-written in `project.module.ts`, as `iam_dept` is no generated module) makes it data-scoped (`@DataScoped`, the spec's own_dept cases), picked with `DeptTreeSelect` and shown by name in the drawer, not listed; decimals show their scale (`toFixed`), dict labels get a tooltip. Hand-written around it: the menu groups `devtools` (系统工具, `db/seeds/codegen/codegen.seed.ts`) and `demo` (生成示例, `db/seeds/demo/demo.seed.ts`, the page's parent = its domain), the `demo.genre` dict, the registration lines (`modules/project.module.ts`, `SEEDS.demo`, the shared index; below) and the Playwright `apps/web/e2e/demo-book.spec.ts` (menu → add → search → edit → detail → export → delete).

`pnpm gen:check-golden` compares Buffers byte for byte and exits 1 for missing, changed or stale files. Changed files show `git diff --no-index --no-color --no-ext-diff` hunks with `--- a/<path>` / `+++ b/<path>` headers; temporary absolute paths are removed. Different bytes still produce a path-bearing notice when Git normalizes line endings or attributes to equality, or returns no text hunk. Git absence produces a plain difference notice; other Git errors fail the check. Missing and stale files are listed as `missing:` / `stale:` paths, so the default output is not a patch to pipe into `git apply`.

To adopt a template/config change, run `pnpm gen:check-golden --write`, then `pnpm gen:check-golden`. Node writes UTF-8 directly. Before any write/delete, it validates the whole G0 target set and Git state: no symlinks, dirty targets, targets flagged assume-unchanged / skip-worktree, or existing untracked targets (including ignored files). New targets may be created. Existing targets are removed before exclusive creation (`wx`), preserving the bytes of any other hardlinks. Stale deletion keeps the existing scope: only `@generated` files in the module's server/web/mobile directories and its named spec/schema/api files; hand-written siblings, other modules and old locale fragments are preserved. On a partial write failure it exits nonzero and lists touched paths, a `git checkout -- <paths>` hint for tracked files, and new files to remove manually; it does not back up or restore files automatically. Template changes and synchronized G0 output must still be committed together, after the regular checks.

## Tree rules (`BaseTreeService`)

- **List**: `list(query)` = the caller's rows (`scopedQb` + `filter()`), ordered `sort_no, id` (`ordered()`; `sort_no` only when the entity maps `sortNo`), as a forest (`forest()`): a row whose parent is not in the result (filtered out, out of scope) is a root. Never paged: trees are small and the page shows them whole.
- **Create**: `parentId` 0 = top level, else the parent is locked through `lockRows` (the caller's scope: 404) and must be enabled (422 `tree.parent_disabled`); the row is inserted with `tree_path = '/'`, then set to `<parent path><id>/`; `create` returns the row as stored (what `GET /:id` answers).
- **Move** (an update with another `parentId`): the live subtree is locked (`FOR UPDATE`) and must all be the caller's (404); the new parent is locked (404), must not be the node or below it (422 `tree.parent_invalid`) and must be enabled (422); then ONE statement rewrites the subtree: `UPDATE … SET tree_path = CONCAT(:path, SUBSTRING(tree_path, :cut)) WHERE tree_path LIKE '<old>%'` (soft-deleted rows too, so paths stay consistent). Paths end with `/`, so `/1/2/` never matches `/1/23/`.
- **Enable / disable** (`PUT /:id/enabled` and `enabled` in `PUT /:id` alike): enabling also enables every disabled ancestor (each must be the caller's: 404); disabling needs no enabled child (422 `tree.child_enabled`). Invariant: an enabled row never has a disabled ancestor. Only when the entity maps `enabled`.
- **Delete**: no child may stay behind (409 `tree.has_children`; a parent deleted together with all its children in one call is fine), then the `beforeRemove` hook, then the soft delete (`softDeleteRows`: the references the entity registers).
- **Data scope**: every read through `scopedQb`, every write after `lockScopedIds` (`lockRows` = lock + a locking read of the current rows, so concurrent moves and adds see each other's committed paths). The scoped-write rule ("the row as the write leaves it must be the caller's") is checked after the write, inside the transaction: `lockScopedIds` on the created row, or on the updated row and its moved subtree; out of scope → 404 and nothing is kept. `iam_dept` is scoped by its own id (`@DataScoped({ dept: 'id', owner: null })`), so its id is unknown before the insert and `assertWritableScope` cannot judge it earlier; the same post-write check covers tree tables scoped by a `dept_id` / `created_by` column. Consequences: an `own_dept` admin can edit its own dept but not add below it (the new dept would not be its own); an `own_dept_tree` admin adds and moves only inside its subtree; nobody moves a subtree they cannot see whole.
- **Hooks** (defaults do nothing): `beforeWrite(set, stored?)` inside the transaction before the row is written (checks of the module's own columns); `beforeRemove(ids)` (references elsewhere that block a delete); `afterMove(ids)` after the commit (the moved row and every row below it).
- `scripts/arch/scoped-access.mjs` follows the class chain: a service extending `BaseTreeService<ScopedEntity>` is held to the same `lockScopedIds` rule as a `BaseCrudService` one.

## Tree page (web)

- **List** (`index.vue`): `useTreeList({ api, filters })` (`core/composables/use-crud.ts`): `query` (filters only), `rows` (the forest), `loading`, `filtered`, `search` / `refresh()` / `reset`, `remove(id)` (confirm → `DELETE /:id` → reload), `expanded` / `toggleExpand()`. `QwTable` takes the forest as `data` (`row-key` `id`; el-table renders `children` as tree rows) with `:default-expand-all="expanded"` and ``:key="`${expanded}`"`` (a new key re-renders every row expanded or collapsed); the first shown column carries the expand arrows (the name column first); columns have no `sortable` (siblings come in `sort_no` order); no `Pagination`, no `selection`, no batch delete, no export. The toolbar has the create button (the page's one solid primary) and a default "expand all / collapse all" button (`lucide:chevrons-up-down` / `lucide:chevrons-down-up`).
- **Row actions**: edit (`modify` + `view`), add below (`create`; `:disabled` on a disabled row: the server refuses it), delete (`remove`; `:disabled` while the row has children); the enabled switch as in CRUD (a refused disable shows the server's 422 and the reload shows the stored state).
- **Form** (`form.vue`): `defineProps<{ id?: number; parentId?: number }>()`; `parentId` starts at the prop, else 0 (top level); the parent field is a tree select over the module's picker lookup (`DeptTreeSelect` for depts: `GET /tree`, enabled rows of the caller's scope) with `:exclude="id"` (drops the row and its whole subtree) and the placeholder `crud.tree.topLevel`, bound through a computed that shows 0 as empty and saves a cleared select as 0. The list opens it with `openDialog(Form, { id, parentId }, { title })`.
- Dept only: the head is a `UserSelect` (`UserPicker`) with `:label="row?.headUserName"` (`useCrudForm` now returns `row`, the loaded `GET /:id` answer, for such joined names).

## Dept only (hand-written, not for the template)

- Head (`head_user_id`, `UserPicker`): `beforeWrite` accepts a new head only if the user is live and in the caller's `iam_user` scope for the route's perm (404); an unchanged head is not judged again (someone with a wider scope may have set it); `list` / `detail` add the head's display name (`headUserName`) only when the caller's `iam_user` scope sees that user (else null: the id stays, the name never leaks).
- `beforeRemove`: users still in the dept → 409 `iam.dept_has_users` (a locking read, so no user moves in before the delete commits).
- `afterMove`: sessions carry their dept's `tree_path` (the `own_dept_tree` prefix): `PermVersion.bumpUsers` for the users of every moved dept, so they reload at their next request; other sessions need nothing (scopes read the paths live).
- `GET /tree`: the picker lookup, enabled depts of the caller's scope for any signed-in user.

## Tree template: what the generator renders

`template` `tree` (`cg_table`) renders the dept sample's generic part: the CRUD templates with tree branches (`kind: 'tree'` in `codegen/crud.ts`, header `@generated by qw-codegen (tree)`) plus its own spec template `test/tree-e2e-spec.ts.ejs`. The G0 sample is `demo_topic` (knowledge topics: `parent_id`, `tree_path`, `title`, `sort_no`, `enabled`; soft-deleted like every table), config `db/seeds/codegen/demo_topic.cg.ts`, page under 系统工具 / 生成示例 after the books.

- **Import rules**: a table with `parent_id` + `tree_path` imports as `tree` with `tree_parent_col` `parent_id`, `tree_label_col` its first `*name` / `*title` column and no export; `tree_path` is never listed or in a form, `parent_id` not listed. Render and save refuse a tree config without `parent_id` + `tree_path` mapped as `parentId` / `treePath` (BaseTreeService's properties; `tree_parent_col` can only be `parent_id`) or without a text label column: 422 C3004 `codegen.tree_columns`.
- **Model**: whatever the column config says, `tree_path` is only in the entity and the VO, `parent_id` only in the form (the parent picker); the label column is listed first (it carries the expand arrows, 240px at least) and no column is `sortable`. `withExport` / `withImport` / `withOptions` / `with_detail_view` / `readonly` are ignored for a tree (dept has none of them).
- **Server**: `<Biz>Service extends BaseTreeService` with only `filter()`; controller `GET /` → `list(query)` as `z.array(<biz>NodeVo)`, `GET /:id`, `POST /` (`@Idempotent()`), `PUT /:id`, `PUT /:id/enabled` (with an `enabled` column), `DELETE /:id`; no batch delete, export, import or options. Schema: `<biz>Query = z.object({ filters })` (no `pageQuery`), `<biz>Vo` with `parentId` / `treePath`, `<Biz>Node` + `<biz>NodeVo` (recursive `children`), `parentId` `z.number().int().min(0).optional()` (default 0 = top level). Perms browse / view / create / modify / remove.
- **Web**: `treeApi` (+ `setEnabled`), the tree page of "Tree page (web)" above, and a form whose parent field is `TreeParentSelect` (`core/components`): the page's own list `GET /` filtered to enabled rows (`browse`, which every user of the page holds; a disabled parent would be refused), minus the edited row and its subtree, 0 ↔ empty. Generated modules have no public picker lookup like dept's `GET /tree`.
- **Spec** (`<domain>-<biz>.e2e-spec.ts`, standard cases only): create paths (top level, below), GET = POST answer, a loaded row PUT back unchanged; the forest (children under their parent by `sort_no`, id; roots at the top level); filters (text contains with literal wildcards, enabled; a match whose parent does not match is a root); parent disabled 422 / unknown 404 on create and move; the move (whole subtree's paths, never below itself 422, to the top and back); enable with ancestors / no disable over an enabled child; delete (children 409, then leaf and parent); 403 per perm, 400 translated, 404, 429, action log, Swagger. No data-scope cases: a tree table with `dept_id` renders `@DataScoped` and BaseTreeService applies it (`iam-dept.e2e` covers those paths), its own scope cases go into a `-extra` spec.
- Hand-written around demo_topic: the migration, the registration lines (`project.module.ts`, `SEEDS.demo`, the shared index), `header.spec` (menu search) and the Playwright `apps/web/e2e/demo-topic.spec.ts` (menu → add root → add child → move → delete).

**Dept stays hand-written (G, not G0).** Re-rendered from the tree template it would lose what only depts do: the head (`UserPicker`, a new head judged against the caller's `iam_user` scope, its name joined only when visible), no delete while users belong to it, sessions of moved depts' users reloaded (`afterMove`), the public picker lookup `GET /tree` (used by every dept filter and `DeptTreeSelect`), seeded names (`seed.dept.*` matched by their texts), phone / email formats, a required `parentId`, sibling-unique names (`unique(parent_id, name, alive)`). Those are hooks and extra routes in generated files, so dept would be a G module anyway; it stays the hand-written reference the tree template follows, and a change to BaseTreeService or the tree page conventions updates both by hand and `demo_topic` through the templates.

**Menus (`iam/menu`, G).** Rendered from the tree template (`iam_menu` got `tree_path` for it; the seed helpers `insertRow` / `upsert` keep the path of every seeded or test menu row), then edited by hand: the kind decides the fields (`menuUnusedFields` in the shared schema: the form hides them, the server saves them empty; a page under a page stays a hidden sub-page; `menuCreate` checks what each kind needs, also on the row a PUT leaves) and the parents (`menuParentAllows`, 422 `iam.menu_parent_kind`); `enabled` flags stand alone (a disabled menu hides its subtree, `countedMenus`), so `MenuService` switches the tree's enable rules off; the page filters names itself (the texts of seeded `menu.*` keys are web strings); a non-root editor writes only perms it holds (403 `iam.grant_exceeds_own`). Rules beyond the tree: route paths unique among siblings (generated `path_key` + unique index, 409), a menu granted to a role is not deleted (409 `iam.menu_granted`), `PUT /sort` renumbers several menus at once (the list's sort mode), and every menu write (create, edit, enable, delete, sort: what `/api/auth/menus` returns) reloads every session and the signed-in browsers' routes (`PermVersion.bumpAll`, after the commit).

**Roles (`iam/role`, G).** Rendered from the CRUD template (config in `qiwu_test`, not committed: name as a seeded name, `data_scope` listed as the `iam.data_scope` dict but set by the data-scope dialog, `menu_link` / `dept_link` kept by the grant dialogs, `is_builtin` listed only), then edited by hand: the options lookup kept (`{ id, code, name }`, root only for root); a new role is never builtin and starts at `own_dept`; builtin roles keep their code and are never deleted, the root role is never disabled and only a root caller edits it (422 `iam.role_builtin`; the list's selection skips builtin rows, `QwTable :selectable`); a role users hold is not deleted (409 `iam.role_has_users`, a locking read) and a deleted role's menu / dept grants go with it; a change of `enabled` or `code` reloads the holders (`PermVersion.bumpUsersOfRole`, after the commit). Grants (perm `iam.role.grant`, dialogs from the list's "more" menu over the module's `grant-tree.vue`): `GET /menu-tree` (every menu) with `GET|PUT /:id/menus` and `GET|PUT /:id/data-scope` (the depts of `picked_depts` from the editor's `GET /api/iam/depts/tree`, the ones it cannot see sent back unchanged; `all` offered to root editors only), each replaced whole with its link switch (`menu_link` / `dept_link`: on = checked + half-checked saved, leaves echoed, a granted parent without granted descendants echoed half-checked so a save keeps it without its subtree; off = as checked; switching echoes the current picks in the new mode), the targets read FOR SHARE (unknown → 404), not for the root role (422), what the change adds through `GrantPolicy.assertMenus` / `assertDataScope` (below), then `bumpUsersOfRole`. Members (perm `iam.role.assign-users`, the hidden page `iam-role-users` `/iam/roles/:id/users` holding the action): `RoleMemberService` extends `BaseCrudService<User>` in the role module, so both lists (`GET /:id/members?assigned=`) read through the users' `scopedQb` and `POST /:id/members` / `/:id/members/revoke` `{ userIds }` first `lockScopedIds` the users (any out of scope → 404, nothing changes); the role row is read FOR SHARE (a delete of it waits and then sees the members); adding passes `GrantPolicy.assertAssignableRoles` per user dept, nobody leaves the root role and non-root callers leave root users' roles alone (422 `iam.user_protected`), the changed users `bumpUsers` after the commit.

**Anti-escalation (`GrantPolicy`; see [permissions design](design-notes.md#permissions)).** One `assert*` method per grant entry, root callers exempt, 403 `iam.grant_exceeds_own` otherwise, and only what a request adds is judged (keeping or removing a grant gives nothing). They share one data-scope judgement (`fits`): a grant that lets a role reach dept D under perm point P needs D inside the caller's own scope for P (the scope a route checking P gives it) and for routes checking no perm; a perm the caller lacks gives it no scope. A role's reach: picked depts (whoever holds it), `own_dept` / `own_dept_tree` the dept (and subtree) of each holder, `own_rows` none, `all` everything (never from a non-root caller). ① `assertMenus(roleId, added)`: the added menus' perms held by the caller, each over the role's reach (also when another, maybe disabled, menu of the role carries it). ② `assertDataScope(roleId, next, prev)`: never `all`; for each current holder what `next` reaches beyond `prev`, for a role nobody holds the picked depts not picked before, over every perm of the role (narrowing passes). ③ `assertAssignableRoles(added, deptId, kept)`: no root or `all` role, only held perms, the role's reach at the user's dept over each of its perms. Indirect grants: `assertMenuWrite(write)` wraps a non-root menu edit — what every enabled role but root gets from its menus (`countedMenus`) is read before and after (the first read locks every menu FOR UPDATE, so menu edits run one at a time), and each perm a role newly gets (new perms, a menu or ancestor enabled, a subtree moved out of a disabled branch) is judged as ①; `assertEnabling(roleId)` (enabling a role, `RoleService.update`): no `all`, every perm of its menus (disabled ones too) held, its reach at its current holders over each of them (disabling passes). Role, menu-link and picked-dept reads are FOR SHARE, so a grant racing another on the same role (locked FOR UPDATE by the role grants) waits for it. `iam-role.e2e -t escalation` covers the three rules through every entry (menu grant, data scope, user edit, assign roles, role members, menu edits, role enabling) and root doing the same.

# Master-sub template: `demo_invoice` + `demo_invoice_line`

`template` `master_sub` renders one module for a master table and its sub tables: the CRUD templates with master-sub branches (`kind: 'master_sub'` and `subs` in `codegen/crud.ts`, header `@generated by qw-codegen (master_sub)`). The G0 sample is demo_invoice (invoice no. unique, buyer, total, issued at, state: dict `demo.invoice_state`) with demo_invoice_line (invoice_id, item, qty, unit price), both soft-deleted, no foreign key, configs in `db/seeds/codegen/demo_invoice.cg.ts` (both tables: one file, one golden module), page under 系统工具 / 生成示例 after the topics.

- **Config**: the master's config has `template` `master_sub`; each sub table's config links to it: `master_table_id` (the master's config id; a restrict reference registered by `cg_table.entity.ts`, so a master with linked subs is not deleted alone — a batch with both is fine) and `sub_fk_col` (the sub's integer column holding the master row's id). Both set or both null, never itself, a sub stays `crud`; else 422 C3007 `codegen.sub_tables` on save and render, like a master without any sub. On save (one transaction): the master must be a `master_sub` config (read FOR SHARE), a master switched to another template releases its subs, and a sub never leaves a `master_sub` master without any; a master saved as `master_sub` before its first sub is linked (the page links from the sub's side) renders only once one is. `.cg.ts` seeds write the link as `master: '<table>'` + `subFkCol` (resolved to the id when seeded, masters first in `CG_SEEDS`). Rendering the master (`CodegenService.renderConfig`: its detail + the linked subs' in id order) renders the whole module; a sub config rendered on its own is an ordinary CRUD module.
- **Model**: per sub (`SubModel`): its entity (`<sub business>.entity.ts` in the master's module directory, `BaseEntity`, never data-scoped; soft-deleted like every row; its own config's `referencedBy` registered there), the rows' property = the sub's business without the master's, plural (`invoice-line` of `invoice` → `lines`; must not clash with a master form field), its form columns without the fk; the sub table needs the key and the audit columns like any template. Its field labels live in the master's fragment and validation domain (`field.demo.invoice.item`, `field.demo.invoice.lines` = the sub's feature name), so a server 400 on `lines.1.item` and the form's cell rule translate the same label; a sub field named like a master field shares its label. `with_import` and `readonly` are ignored (a document is saved whole through its form); export, options and the detail drawer (master fields only) work as in CRUD.
- **Server**: `<Biz>Service extends BaseCrudService` + `detail(id)` (the row in scope, else 404, with its rows by `sort_no` when the sub has one, then id), `create` (the row, then its rows, answers `detail`), `update` (the base update locks the row in scope first; a list sent is the whole new list, one left out is kept), `remove` = the base soft delete (the master's entity registers each sub by its fk as `cascade: true`, so the rows go with it in the same transaction), `save<Rows>` per sub: the live stored rows of that master read after the lock; a sent row with the id of one of them is updated, one without an id inserted (`<fk>` set by the server), stored ones not sent soft-deleted (`softDeleteRows`), any other id → 404 and the whole write rolls back. Controller: `GET /:id` and `POST /` answer `<biz>DetailVo`. Schema: `<sub>Input` (+ optional `id`), `<prop>: z.array(<sub>Input).max(SUB_ROWS_MAX)` in the create body (required; the update body is its partial), `<sub>Vo`, `<biz>DetailVo`.
- **Web**: the list page as CRUD with an 880px form dialog; `api.get` answers the detail; the form puts each sub's rows into the core `QwEditTable` below the fields: one `el-form-item` per cell (`prop` `lines.<index>.<field>`, the rule from `zodRules(<sub>Input)`), so the dialog's form validates every cell on save; cells reserve their error line (styles/element.css), so a message coming or going never moves the save button; dict radios become selects there, uploads text inputs. el-table renders a column's slot once with `$index` −1 while collecting columns: `QwEditTable` skips it, else a hidden cell would join the form and fail unseen.
- **Spec**: the standard CRUD cases (bodies carry empty row lists) plus, per sub: create with rows (order, ids, fk) = GET; the update diff (changed / added / deleted by id — the deleted row stays, marked —, left out kept, `[]` empties); a row id of another master → 404 with nothing written (the master fields sent with it neither); delete takes the rows (soft); 400 on a bad row field with its path and translated label.

Widgets (form / detail): input → `wd-input` (maxlength); textarea and richtext → `wd-textarea` (rich text edited as its HTML, sanitized by the server on save; the detail shows it with `rich-text`, sanitized on GET /:id); switch → `wd-switch` (detail: the dict label); select / radio with a dict → `QwDictSelect` (detail / list: `dictText`); number → `wd-input-number` (range, decimal scale and step; bound through `numOf`, as the component hands back `''` when emptied and its formatted text when first shown); date / datetime → one `wd-datetime-picker` per page (`useDatePicker`: the API's `YYYY-MM-DD` local day or ISO instant); image-upload → `QwUpload biz-tag="cover"` (the public URL, detail `wd-img`); file-upload → `QwUpload` (`<id>/<name>`; shared `uploadsOf` / `uploadText`, as the web's `uploadField`); dept-tree-select → `QwDeptPicker`; user-picker → `QwUserPicker source="iam"` (`usersOf` / `userId`). Left out, with an explicit limitation: secret columns (write-only; a required one makes the mobile create fail with the server's 400), list filters other than the one search, dept / user names in the detail (the id, like the web's detail outside the caller's tree), per-cell row messages.

Generated code prints DB texts only into the locale fragments (JSON): a `.vue` file never holds a comment or label from the database (`</script>` would end the block even inside a comment); every text is `t()` of a literal key (i18n-check rule 2), colours only through the global classes of `App.vue` (no page styles). The registration lines add the `pages.json` entries of the `pages-biz` subpackage (index, detail, form unless read-only) and a hint on an entry point (e.g. a workbench shortcut); the generator edits no existing file. The G0 demo pages are registered in `pages.json` without an entry point (reachable by URL; `mobile/e2e/mobile-codegen.spec.ts`), so `build:mp-weixin` and `mp-size` check them; before a release, drop their 9 `pages.json` entries and `mobile-codegen.spec.ts` but keep the sources (they are golden for `gen:check-golden` and `codegen-render.spec.ts`; docs/mobile.md, release checklist).
