# 原生考勤

员工使用栖梧移动端的“打卡”入口签到、签退和查看本人记录，不需要钉钉账号或打卡机。考勤使用独立的 `oa` 功能能力，审批功能停用不影响原生打卡入口；服务端仍执行租户套餐与登录检查。

## 时间和记录

每个租户有一份考勤规则：是否启用、IANA 工作日时区、定位模式及保留天数。初始值为启用、`Asia/Shanghai`、不定位、保留 180 天。初始化不覆盖管理员的修改、停用或删除，也不制造任何打卡记录。

每天只有一组上班签到和下班签退。工作日由服务器按租户配置的时区计算；时刻使用服务器处理请求并取得当前规则、地点锁后的 UTC 时间。客户端不能指定员工、历史日期、时刻或来源。签退要求同一工作日已有签到，且签退时刻严格晚于签到。

跨午夜视为新的工作日。因此前一天的签到不能用于新一天签退。跨夜班、多班次、排班、节假日、补卡和离线补传未实现，不能将这一规则用于需要这些能力的考勤结算。

记录保留打卡时的用户、部门、工作日、时区、规则快照、动作及校验结果；规则或地点后续变化不改写历史记录。原始记录没有任意改时间、代打卡或删除的业务接口，也不提供助手代打卡工具。

## 位置授权

`none` 模式不调用设备定位。`site` 模式由管理员维护固定办公地点、经纬度、允许半径和精度阈值，员工点击打卡时才请求一次前台 WGS84 定位。服务器计算球面距离，使用未取整结果判断边界。

拒绝授权、不支持定位、定位超时、坐标不合法、精度不足、地点停用或超出范围时明确拒绝，不自动退回不定位模式。定位和网络请求期间禁用签到、签退按钮，防止同时发出动作。

员工原始经纬度只用于本次校验，不写入考勤表；打卡接口的请求审计和 HTTP 日志也遮挡位置及经纬度字段，包括校验失败的请求。考勤表保存固定办公地点快照、距离、精度及校验结果，没有完整轨迹。固定地点本身属于管理员配置，不等于员工位置。

客户端位置可能被设备或软件伪造，目前没有 Wi-Fi、蓝牙、硬件证明或设备级防作弊。需要这些能力时应另行设计，不能将普通定位范围校验当作可靠在场证明。

## 网络异常和重复操作

每次动作带仅属于本人的随机请求标识。服务器按员工串行处理，并以“租户、员工、工作日、动作”和“租户、员工、请求标识”两组持久唯一约束防重。相同请求和相同参数返回原结果；相同标识换参数、同日同动作的另一请求返回冲突。

手机端遇到结果不确定时，先查原请求结果，再刷新今天状态，不自动重新发送 POST。确认未找到结果后，使用者才能选择重试；重试保留同一请求标识和本次定位。认证刷新也不会自动重放打卡写请求。

若原请求未找到且服务器工作日已变化，旧请求不会被改造成新一天的打卡，需重新确认新动作。找到旧结果时保留原结果的工作日。位置和请求标识只保留在当前页面控制器内存，确认结果、退出页面或切换账号时清理，不写离线队列或持久存储。

## 本人和管理查询

本人记录始终限定当前用户，管理权限不能扩宽“我的”接口。管理查询另需权限和部门数据范围；root 仍受租户隔离。历史记录使用当时部门快照，不因员工后来调部门而搬移历史数据。工作日保留打卡原值，汇总所选时区只决定请假、出差的UTC日覆盖区间；历史记录的时区快照另行展示，不把它们回算到新工作日。

部门日汇总按当日有打卡或批准假勤的“用户+当时部门”快照对列出活动主体，total不是员工总人数，也不是完整出勤花名册；同一员工可能有多个可见部门快照行。本人无活动也返回一行零记录汇总。日汇总只描述记录和批准的请假、出差时间段。没有记录不表示旷工，有批准假勤不表示已完成签到；没有排班和节假日日历时不判迟到、早退、工时或扣薪。假勤关联只展示核验所需的类型、状态和时间，不暴露请假事由、出差目的地、费用或附件。原始打卡不会因审批状态变化被删除。

保留天数允许配置在 30 至 730 天。`oa.clock.retention`任务按租户配置清理，每批最多500条、每次最多5000条，在锁内复查当前规则和租户状态并响应取消。默认首次安装每日04:15执行，管理员调整、停用、改名或删除后初始化不覆盖；测试环境默认停用。日历截止日与UTC已经过天数同时满足才清理；不提供任意指定员工或日期的删除接口，不清理当天记录。部署方应按业务需要设置保留期，并将数据库备份和备份过期策略一并管理。

## 接口

所有接口位于 `/api/oa`，沿用登录、租户上下文、标准响应及错误状态。

| 接口                                     | 用途                                             |
| ---------------------------------------- | ------------------------------------------------ |
| `POST /clock-records/punch`              | 本人签到或签退，服务端时间、按本人限流和持久幂等 |
| `GET /clock-records/today`               | 服务端当前时刻、工作日、规则摘要与今日记录       |
| `GET /clock-records/requests/:requestId` | 本人的持久请求结果                               |
| `GET /clock-records/mine`                | 本人原始记录，支持工作日和动作筛选               |
| `GET /clock-records/mine/:id`            | 本人的原始记录详情                               |
| `GET /clock-records/admin`               | 管理权限和部门数据范围内的原始记录               |
| `GET /clock-records/admin/:id`           | 同样受数据范围控制的管理详情                     |
| `GET /clock-summaries/mine`              | 本人单日汇总，无活动仍有空结果                   |
| `GET /clock-summaries`                   | 可见活动主体的单日汇总                           |
| `GET /attendance-sites/options`          | 当前启用办公地点选项                             |
| `GET /attendance-policies/current`       | 具有规则查看权限者读取当前配置                   |
| `PUT /attendance-policies/current`       | 具有修改权限者调整规则                           |
| `/attendance-sites`                      | 具有对应权限者管理办公地点                       |

服务端 400 表示输入不合法，403 表示权限不足，404 包括 OA 功能未开放、对象不存在或越界，409 表示请求或动作冲突，422 表示当前规则、定位或前置动作不满足，429 表示提交过密。客户端展示服务器的具体提示，不按共用业务错误码猜测位置失败原因。

## 平台差异和部署验收

H5 用于开发和自动化验证。微信小程序需要部署方配置合法 API 域名、定位用途和平台所需授权；App 需要正确的前台定位权限和发布配置。应用只声明 Android 前台粗略/精确位置、iOS 使用期间位置及小程序 `getLocation`，没有后台持续定位权限。

构建成功不能证明设备已经授权或定位可用。上线前分别记录真实 App 和小程序的授权、拒绝授权、精度不足、越界、签到、签退、重复点击、断网后查询结果、账号切换和午夜边界。设备系统、平台审核和位置服务差异应在实际部署环境验证。

原生能力在没有任何钉钉配置时仍须可用。现有钉钉打卡机若将来接入，应作为独立的可选同步来源，另行确定账号匹配、去重和失败处理，不能代替本系统的权限、时间或工作日判断。
